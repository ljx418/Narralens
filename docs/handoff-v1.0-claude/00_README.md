## 使用顺序

1. 阅读 `01_CURRENT_STATE.md`，先理解已实现事实、未提交工作和禁止声明。
2. 阅读 `02_V1_GAP_MATRIX.md`，确认 PRD 尚未关闭的能力。
3. 阅读 `03_REMAINING_ROADMAP.md`，按唯一允许的阶段顺序推进。
4. 每个阶段开工前使用 `04_STAGE_GATES.md` 建立独立开发/验收计划并完成内外审。
5. 从 `05_D421_RESUME_RUNBOOK.md` 的中断点恢复，不要重做已经通过的 fault/race、UI 或 64 MiB 门禁。
6. 按 `06_AUDIT_AND_EVIDENCE_RULES.md` 生成真实证据和审计结论。
7. 把 `07_CLAUDE_CODE_START_PROMPT.md` 全文交给新的 Claude Code CLI。
8. `08_CANONICAL_SOURCE_INDEX.md` 是必须核对的权威原文清单；本包只覆盖状态与执行顺序，不替代 PRD/架构原文。
9. 每次需要独立外审时，把 `09_EXTERNAL_AUDIT_SESSION_PROMPT.md` 复制到新的 Claude Code 只读会话，并替换其中占位符。

## 冲突优先级

发生冲突时按以下顺序处理：

1. `docs/01_PRD.md` 的冻结规格和明确“不做”；
2. 用户已批准的六步开发循环与 `docs/09_Development_Workflow.md`；
3. 当前阶段经内外审通过的专项计划；
4. 本包的 2026-10-15 状态覆盖层；
5. 旧总览中的历史状态文字。

核心状态文档已同步到“D4.2.1 内审通过、外审待完成”；接手者不得在外审关闭前改写为 Gate 通过，也不得借同步状态修改 PRD 范围。
