# V1 外部文档审查说明

版本：v1.0（2026-10-12）  
阶段：单一版本六步循环第 4 步——开发文档迭代  
状态：V1 原型与开发计划已批准；内部独立审查与两轮 Claude Code CLI 外审已闭环；实际代码开发未获批准

## 1. 外审目标

外审只判断现有文档是否足以安全进入 V1 实际开发，不执行代码开发，也不把原型交互或静态页面当作真实功能验收。审查应独立复核以下问题：

1. PRD 的 P0 与非功能规格是否全部落到架构实体、开发阶段、测试方法和证据要求。
2. 获批原型是否忠实表达 PRD，不增承诺、不漏关键路径，失败、恢复、锁定与回滚状态是否明确。
3. 目标架构是否能支撑逐镜头可控、局部修改、真实渲染导出和可审计证据链。
4. D1—D7 的依赖、先后关系、阶段门槛、回退条件和出门条件是否可执行。
5. 验收计划是否包含用户场景、操作步骤、量化门槛、真实数据和可复核证据，是否存在虚假验收空间。
6. 单一版本六步循环及四次授权是否一致落盘，是否可能在外审或实际开发批准前误入生产代码。

## 4. 外审必须给出的结果

每条意见需包含：严重级别、所涉 PRD/用户场景、文件与章节、可复现问题、风险、建议修订、关闭证据。严重级别统一为：

- 致命：无法安全实施、可能造成数据破坏或使核心目标不可达。
- 重大：规格缺失/冲突、架构或验收不足以指导实现、存在明显虚假验收风险。
- 一般：不阻塞实施，但降低一致性、可维护性或审计效率。
- 建议：非规格性改进，不得借此扩大 V1 范围。

最终只能给出以下一种结论：

- `可进入实际开发审批`：致命与重大问题均为 0；一般问题已明确归属且不影响 D1 开工。
- `修订后复审`：存在任一致命或重大问题，或外审无法从文档获得可复核证据。

## 5. 外审后的状态转换

1. 若结论为“修订后复审”，留在第 4 步，完成修订、内部复审、再次外审。
2. 若结论为“可进入实际开发审批”，仍不得自动进入第 5 步；必须获得项目负责人的独立“实际开发批准”。
3. 获得实际开发批准后，按 D1—D7 逐子阶段执行计划、审计、实现、真实数据测试、PRD 检视、验收和证据落盘。
4. V1 只有完成第 6 步阶段性验收、可视化验收报告与 Git 仓同步，并获得版本出门批准后，才允许开启 V2。

## 6. 是否需要 Claude Code CLI 外审

建议需要。原因是本次进入实际开发前的判断跨越 PRD、交互、架构、追踪矩阵、验收门槛和 Draw.io，独立上下文审查有助于发现内部审查的共同盲区。其审查范围应严格限定为本清单的 14 个文件，输出按第 4 节格式；当前不存在可供其声明“代码实现完成”的生产代码基线。
