## 1. 产品一句话
叙镜是由外部 Agent 驱动的本地视频制作服务与可视化工作台。Codex、Claude Code CLI 或 DSH 通过入口 Skill、Skill-Lib 与 MCP 发现和调用能力，组织研究、脚本、分镜和制作流程；叙镜负责实际媒体处理、持久工程、任务执行、预览、审批、版本和交付。用户在终端表达意图，在工作台观看和选择，两方共享同一项目事实。

## 2. 零号用户与首发场景
零号用户是单人创作者，已有 Cursor/Codex 和本地剪辑相关工具，希望尽可能复用开源项目、减少手写代码。首发内容为中文时政观点视频：通常 10–12 分钟，必要时 15 分钟；强调背景、因果、争议与结论讲清楚。

### 2.1 首条内容形态
- 平台优先：B 站；输出默认 16:9、1080p、30fps，可配置。
- 结构：片头钩子 → 背景/问题定义 → 来龙去脉 → 核心论证 → 反方/边界 → 结论。
- 章节：脚本中明确，画面不默认做明显章节切换动画。
- 小分镜：通常 5–10 秒；遇到原片、地图、数据图、关键引用可更长。
- 声音：旁白作为主时间轴；支持本人录音优先，后续接授权 TTS。
- 封面：AI 辅助生成，需与事实和视频主旨一致；不伪造现场。
- 标题：多候选，兼顾吸引力与事实准确，不允许“标题结论”与正文冲突。

## 3. 核心问题
现有“一键生成视频”工具往往不可控：一个镜头不满意会触发大范围重做，创作者无法知道改动影响、费用和来源。专业剪辑软件可控但前期研究、分镜和素材准备耗时。叙镜要把两者结合：AI 负责提案与劳动密集型环节，人负责观点、选择与最终导演判断。

## 4. 核心体验原则
1. **终端与工作台协作**：终端负责目标表达和流程组织，工作台负责影片、方案、差异和审批；项目、选区、决定自动互通，不要求用户复制内部 ID、JSON 或日志。
2. **先提案，再生成**：先比较分镜设计，再为选中方案生成/获取素材。
3. **默认局部影响**：改镜头不改旁白；改局部不重做全片；共享对象变更先显示影响范围。
4. **锁定是真锁**：锁定必须作用于实际工程写入路径，而非只禁用按钮。
5. **所有 AI 产物可追溯**：来源、生成模型、许可、费用、时间、版本可查。
6. **事实与视觉分开审核**：资料可作为事实依据，不等于素材有再利用许可。
7. **失败可恢复**：任何生成、适配或渲染失败不得损坏已确认工程。

## 5. 目标用户流程
### 5.1 创建项目
用户粘贴与 ChatGPT/智能体的聊天结果，或导入标准任务包；可附 PDF/网页摘录、自有视频、录音。

也可直接向外部 Agent 口述目标；Agent 通过 MCP 创建持久任务和真实工程。入口 Skill 指导能力发现与恢复，不负责保存唯一状态。关闭工作台不会删除生产项目；当前 M5 临时体验启动器仍只用于历史演示，不作为新生产入口。

系统先生成“创作任务摘要”：主题、核心观点、必须保留原话、待核验主张、目标时长、账号风格、资料清单。用户只纠正关键内容，不需要写 JSON。

### 5.2 研究与脚本
系统把主张分为：已证实、存在争议、作者判断、待核验。研究输出保留来源与时间。基于确认后的任务生成章节、大纲、逐字稿和每段视觉意图。

### 5.3 粗分镜与素材
外部 Agent 生成结构化分镜方案、素材需求与候选来源；可复用 OpenMontage 的方法或适配器，不强制嵌套启动另一名 Agent。叙镜验证并保存这些结果，工作台先展示“怎么讲”的方案，不默认为每个候选生成昂贵素材。

### 5.4 精修
进入统一工作台：左侧/中央实际播放器，右侧导演面板，底部完整时间轴。选择镜头或时间段后，可：
- 替换画面/素材；
- 生成 3–6 个结构不同的分镜备选；
- 调整入出点、缩放、裁切、字幕、速度和关键帧；
- 锁定画面、旁白、时长；
- 查看修改前后差异、影响范围和费用；
- 应用、撤回或恢复历史版本。

### 5.5 标题与封面
成片内容稳定后，基于“事实摘要 + 核心观点 + 受众”生成标题候选和封面提示/候选。必须显示与正文不一致的风险提示；用户确认后保存为交付资产。

### 5.6 交付
导出 MP4、字幕、来源/许可清单、标题/封面、版本与生成记录。第一阶段手动发布；后续导入播放数据和评论，生成下一版工作流建议。

## 6. 工作台功能范围
### P0（必须）
- `P0-01` 项目创建与任务包导入。
- `P0-02` 章节/脚本/镜头列表。
- `P0-03` 真实播放器与统一时间码。
- `P0-04` 全片时间轴 + 局部精修模式。
- `P0-05` 镜头/区间选择、逐帧定位。
- `P0-06` 3–6 个分镜提案对比。
- `P0-07` 画面/旁白/时长分项锁。
- `P0-08` 本地素材导入、来源和许可状态。
- `P0-09` 局部改动差异确认。
- `P0-10` 版本、撤回、恢复、冲突提示。
- `P0-11` 真实工程重开与 MP4 导出。
- `P0-12` 标题与封面候选工作区。
- `P0-13` 基础发布前检查。

### P1（首月）
- 完整 10–15 分钟项目稳定运行。
- 账号风格模板与 StyleProfile 版本。
- TTS/ASR/字幕对齐适配。
- 素材检索与生成服务适配。
- 章节导航、评论与反馈锚点。
- 预算、失败重试、任务队列。

### P2（后续）
- 多账号批量生产。
- 自动化反馈学习与模板建议。
- 多人协作与权限。
- 自动发布（单独验收）。
- SaaS/多租户（需重新评估许可）。

## 7. 明确不做
- V1 不做多租户、自动发布、复杂跨镜自由变形、完整专业 NLE 替代，也不建设通用插件市场。
- 不把未经授权的 B 站/YouTube 素材下载视为默认能力。
- 不把 AI 重建画面当作新闻/历史证据。
- 不允许模型直接覆盖已锁定工程或扩大选区。
- 不让 UI 演示代替真实编译和真实 MP4 验收。

## 8. 非功能要求
- `NFR-01` 本地优先：素材和凭据默认留在本机；需外传时逐任务记录。
- `NFR-02` 可恢复：崩溃后可检测未完成事务并恢复到最后已提交修订。
- `NFR-03` 可观察：长任务显示真实阶段、失败原因、费用状态；无真实百分比时不显示假进度。
- `NFR-04` 可测试：关键接口有契约测试；编辑改动可通过帧数、哈希、ffprobe、帧采样验证。
- `NFR-05` 性能：10–15 分钟、100+ 镜头项目仍能流畅导航；重型生成异步执行。
- `NFR-06` 可访问：键盘逐帧、可见焦点、减少动态效果、状态不只靠颜色。

## 9. 成功指标
第一阶段成功不是“按钮很多”，而是：零号用户能从真实项目中找到任意镜头/语义位置，提出一个局部要求，比较方案，保留旁白，应用修改，撤回，再重开项目并导出真实 MP4；且已确认内容没有被无关重生成。

首月成功是：同一流程完成一条完整 10–15 分钟时政观点视频，包含标题、封面、字幕、来源记录和发布前检查。

## 10. 规格变更门槛

- P0、NFR 或“不做”范围发生变化时，必须先更新本 PRD、`07_Decisions_Open_Issues.md` 和 `11_V1_Traceability.md`，再调整架构或计划。
- D1 只能基于真实上游事实调整 Adapter 契约和代码路径；若改变用户体验或产品范围，必须重新进行原型与 PRD 审批。
- 任何静态页面、mock、手工拼接 JSON 都不能把 P0 条目标记为已实现。

## 13. 端到端示例与人工判断点

1. 用户向 Agent 提供观点、资料和 3 分钟目标；工作台出现持久任务摘要。第一次事实/观点审阅后进入脚本。
2. Agent 提交章节、逐字稿和 3 个分镜方案；用户可在工作台选 B。选择事件自动提供给 Agent。
3. Agent 读取授权范围，检索已允许来源或复用本地资产；新付费/外传超出授权时等待。Host 保存 receipt、来源与输出，随后准备声音、字幕和初稿。
4. 用户选第二镜要求换画面；Agent 读取当前 selection，准备局部方案。工作台显示前后预览与保留旁白/时长。人工确认后提交。
5. 中断 Agent 并关工作台，重新打开同一项目，换 Agent 读取任务状态继续；不会自动重做已经确认的步骤。
6. 用户审阅标题/封面及 QC；导出两次之间修改一镜，对照真实产物和工程版本。人工确认内容与审美，最终发布仍由人执行。

低风险、可逆的准备工作可在用户事先批准的范围内连续执行。高成本、外传、超范围写入和发布必须遵守显式授权。允许按项目/阶段预授权，但必须绑定输入/范围/成本与有效期；超出后重新确认。Skill 中写“已批准”不构成授权事实。

## 14. 服务发现与执行的产品要求

- 工具可列出名称、版本、输入输出 schema、能力范围、可用性及不可用原因；发现不是自动安装服务或插件。
- 长任务返回稳定 job ID、当前阶段、查询与取消入口；Agent 断线不等于取消，取消确认前不得显示已取消。
- 操作带项目/输入版本、幂等键；重试返回已有结果，异内容同键冲突。费用未知必须如实显示 unknown。
- 媒体通过受控 asset/artifact 引用交付，不在 MCP 返回完整视频二进制或任意服务器绝对路径。
- 用户审批、Agent 调用、人工编辑共享项目事实和审计记录；任何通道不能跳过原有 Coordinator。
- Codex/Claude Code CLI/DSH 按真实客户端逐个测试；DSH 支持能力尚未复核，未支持的 MCP transport 或 Skill 加载需兼容适配，不先承诺三端等价。

## 15. 发布层级与验收口径

| 里程碑 | 可以声明 | 不可声明 |
|---|---|---|
| AD-S2 最小成片闭环 | 一个真实 Agent 经 MCP 用本地授权素材创建持久项目、制作并导出 60–180 秒影片 | 全自动在线下载/TTS/全部 P0 或 V1 已完成 |
| AD-S4 Agent 驱动创作 Beta | 在线许可检索/下载、授权配音、字幕封面、审批、恢复与交付链真实通过 | 没有全部 P0/NFR 证据时不得声明 Gate V1-P0；没有全 P1 不得 V1-Full |
| AD-S5 V1 最终验收 | 全部 P0/P1/NFR 与 AD-E01..21 有实际证据、独立审查及人工签署 | 任何 partial/blocked/未执行能力不得算全绿 |

原 M6 的 V1-P0 与 M7 的 V1-Full 声明门限保留，新阶段只映射承诺，不顺便关闭历史 Gate。3–5 分钟章节与完整 10–15 分钟母项目仍必验；工作流组织方式变化不缩减原交付内容。

## 16. R2 体验优化与本地生成边界

### 16.1 需求启发与内容审阅

Agent 先读取已有任务与用户资料，识别缺口，再给少量有区分度的问题与可预览风格例子。工作台“创作简报”显示已确认/推断/待答，每项可独立修改。默认先问影响路线的主题、受众、时长和素材条件，其余逐步补齐；用户可先用明确标注的默认值试做。Agent 提问是结构化 artifact，用户回答是带版本 Decision，不要求工作台内另部署第二个模型。

AD-E03 被用户标记待讨论但未附原因：保留“资料/主张/脚本分层、事实核验与观点区分”的原承诺；建议正文为主、来源按需展开、只集中审阅争议/缺证项。此建议未自动获得认可。

### 16.2 两层工作流视图

默认业务图：简报→研究/脚本→分镜→素材/声音并行→初稿→精修→QC/交付。节点显示当前版本、输入输出计数、真实状态、负责人和等待原因。点击打开可编辑详情；高级视图才展开 Comfy 模板和执行节点，普通创作者无需理解 KSampler 等内部节点。

编辑输出创建新 artifact version，计算下游影响；仅标记直接/传递消费者 stale，不删除旧结果或重置独立分支。用户批准重算范围后再执行。已进入工程的内容保持原 committed snapshot，直到新结果获批采用。图同时区分步骤状态与执行尝试，历史失败不得被最新绿灯覆盖。

### 16.3 素材规划与本地生成策略

素材任务按 source intent 分类：事实资料、真实再利用素材、AI概念说明、装饰/转场。先查本地缓存与已授权素材，再轻量检索，最后下载/生成；是否采用此顺序可由创作策略配置，不强制每镜AI化。脚本还在改时可先研究参考，不提前批量下载高清视频或生成所有方案。

本地 ComfyUI 是可选制作后端，不能将大量现有 workflow JSON 直接全部暴露给模型。先登记与固定模板，再提供概念图、图生视频、首尾帧、后期等语义能力；阶段内至少验证一条图像和一条短视频完整链。未通过的模板显示 blocked。只有当前依赖/节点/模型/质量/许可/资源探针均通过，才成为可选择能力。

专场按“主题化连续片段”理解，另增 AI转场；用户是否仅指“转场”仍待明确。主题连续性用统一概念/风格/参考图约束，不承诺任意模型跨镜身份、物理规律或首尾帧精确命中。科学/技术概念中的精确标签、流程和数值不用生成模型臆造；需要确定性的可编辑图形层。对生成质量不合格可保留可编辑静态说明图或普通转场。

### 16.4 并行、重算和资源体验

DriverSession 只限制谁推进项目决策；不限制已授权任务图的并行。多个下载、多个章节渲染、声音合成可作为独立 child jobs；是否并行由依赖与 IO/CPU/RAM/GPU容量决定。单显卡大模型默认按独占槽排队，实测资源允许才增加 GPU并发；不能为每个章节复制一套模型。

操作队列时只取消属于当前任务的项，不清空共享 Comfy 队列或打断其他项目。取消后晚到结果进入隔离区，不自动采用。禁止将使用本地 GPU 解释为“零耗时/零成本”；区分 API费用、运行时间、显存和磁盘。

## 17. 实时工作流与服务监控

工作台常驻“当前流程”和“服务状态”入口。流程图是项目/步骤/attempt的实时投影，监控是跨项目的本机服务与资源视图；两者可相互定位，不能用“服务在线”推定某节点成功。

工作流节点显示排队、等待资源、执行中、等待用户、完成、失败、已取消、结果过期，状态与进度分开。无实际百分比则显示阶段、耗时、已完成/总子任务；长时间无进度但心跳正常显示“仍运行、暂无新进度”，不擅自判失败。失联时冻结最后已知数据并标时间，不继续跑假进度。

监控面板默认提供：服务总览、运行/排队任务、资源占用、最近告警与脱敏日志、启动/停止/恢复说明。服务卡显示实例与版本、所需依赖、探测结果与采样时间；Comfy在线但模型缺失属于对应能力blocked/degraded，不把所有能力标ready。显示哪些项目/节点受影响，点击告警可定位工作流节点。

默认设计目标：Host状态事件正常连接下p95≤2秒呈现；服务采样5秒、超过15秒未获得新样本则标unknown/stale。以上是待实现验收指标，不是当前性能声明；重任务阶段需验证监控采样不显著干扰生成。服务停机或Host自身故障时，工作台仍需呈现连接失败和最后已知时间，独立supervisor提供有限本机健康信息。

仅用户可见的服务控制动作可执行，且检查服务归属、活动任务与权限：重启会中断任务时先展示影响、等待/取消/恢复选项；共享或非本项目启动的Comfy不提供任意kill/全局清队列。错误与日志不包含token、完整prompt/个人资料、环境变量或任意文件读取入口。资源无法采集时显示“不支持/未知”，不按0或正常处理。
