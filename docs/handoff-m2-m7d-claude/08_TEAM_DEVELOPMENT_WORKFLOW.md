# 团队四波次开发流程

## 1. 流程目标

团队以“四个垂直波次”推进，不以几十个小 ticket 反复停工。波次内由 Claude Code 连续完成设计、实现、增量测试和证据；模块检查点快速失败，波次末才进行完整组合验收与独立外审。

质量来自提前冻结跨模块契约、真实自动化验证和组合回归，不来自增加会议或重复写审查报告。

## 2. 角色分离

| 角色 | 职责 | 参与频率 |
|---|---|---|
| 项目负责人 | 批准整波方向、高风险/付费/外传、Wave 3/4 人工体验和 Gate | 每波开工/出门；高风险例外 |
| Claude Code 实现会话 | 连续实现整个波次、自动修复、增量证据和内部组合审查 | 波次全程 |
| 独立审查会话 | 只读冻结组合 commit/证据，复跑关键 Gate | 每波一次 |
| 自动测试 | 合同、代码、媒体、恢复、Headless UI 和旧回归 | 每模块增量 + 波次末全量 |
| 人工验收 | 内容、审美、headed、真实设备和最终签署 | Wave 3/4 集中执行 |

实现会话不能自签独立外审；自动化不能冒充人工。但模块级通过不要求等待独立审查。

## 3. 单波次七步闭环

1. **现场与契约一次冻结**：核对 SHA/工作树/前门，冻结整波接口、状态机、持久格式、case 和禁止项。
2. **最窄真实链**：先打通一条真实垂直路径，尽早暴露跨模块设计错误。
3. **模块连续扩展**：按依赖顺序实现；每个模块运行增量测试、fitness 和受影响回归。
4. **失败聚类修复**：按根因批量修复；普通工程失败不请求用户逐项批准。
5. **波次组合验收**：在组合树运行全量 check/build、逐 case、真实媒体/重启/导出、Headless 和回退。
6. **一次内审与一次外审**：内部从架构、代码、体验、验收四角审查；冻结 commit 后独立外审。仅架构/持久合同变化才需要全量重审。
7. **出门与下一波**：同步架构、路由、追踪、登记册和 evidence，输出唯一下一波范围。

## 4. 模块检查点

模块检查点自动执行，不生成完整阶段报告：

- 目标合同和失败测试先红后绿；
- 受影响测试、TypeScript 和生产 build 通过；
- 对应 AC fitness 通过；
- legacy 入口和旧 case 未删除/弱化；
- evidence manifest 追加 case、命令、日志和 SHA；
- 无 BLOCKER/MAJOR、高风险外部动作或需要用户输入。

检查点通过即继续本波次下一模块。MINOR 在波次 backlog 集中处理，不制造中途停工。

## 5. 正式审查策略

### 开工前审查

只审一次整波计划，重点找跨模块返工源：接口重复、临时模型、持久格式不兼容、下游无法消费上游产物、验收缺真实链。

### 波次末内部审查

一次覆盖四个视角：

- 架构：AC 契约、依赖、数据所有权、回退；
- 代码：可维护性、错误、并发、迁移、兼容；
- 体验：真实用户链、状态词、失败恢复；
- 验收：逐 case、真实证据、旧回归、声明口径。

### 独立外审

绑定一个冻结组合 commit。修复后若只改局部实现且没有改变架构/持久合同，重跑受影响 case、全量 smoke 和外审指明的复验项；不机械重做全部文档审查。改变 AC、schema major、DB 持久格式或用户承诺时才重开整波审查。

## 6. 分支与提交

每波一个主分支，例如 `migration/wave1-controlled-runtime`。模块可有短期 worktree/提交，但必须合回同一波次候选并在组合 commit 复验。一个提交保持一个可观察能力，便于 bisect；正式 Gate 绑定组合 commit。

禁止 main 直接大改、force push、reset 用户工作或用多个长期分支形成互不兼容的实现。

## 7. 停止和自动继续

### 自动继续

类型/编译失败、局部测试失败、adapter 小差异、可复现 race、文档小错和普通性能优化均由 Claude Code 在波次范围内自动修复、复验和继续。

### 必须停止

- 数据损坏、commit 不确定、回退失败；
- 双写、第二 timeline、native/provider 绕过；
- 未授权费用、外传、凭据/隐私风险；
- 需要用户提供真实素材、内容判断、headed/人工体验或架构取舍；
- 真实 Gate 连续两轮没有减少失败数；
- 外部 422/429/529 或环境故障使真实性无法继续。

停止时给出根因、影响、已尝试、证据、技术路线和下一最小用户动作。

## 8. Headless 与证据

- 自动 UI 一律 Headless、静音、隔离 profile、无窗口、不抢焦点；结束清理进程。
- headed 和人工体验集中到 Wave 3/4，并提前协调；未运行则明确 `NOT_RUN`。
- 每波证据目录：`docs/evidence/WAVE<n>/`，下设模块 case，但只有一份波次组合 manifest/报告。
- 失败尝试保留；同根因可共用修复说明，但每个 case 保留直接断言。

## 9. 最小交接输出

每次异常停机或波次完成时输出：`current_wave`、`module_checkpoint`、repo/upstream SHA、已实现/已验证、逐 case 状态、evidence、AC deviations、回退、内/外审、下一允许波次、blocked actions、用户动作。
