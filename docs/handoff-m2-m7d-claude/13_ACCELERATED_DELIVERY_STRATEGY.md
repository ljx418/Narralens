# 大步高质量交付策略

版本：1.0

状态：`APPROVED_PROCESS_DIRECTION`

目标：减少小阶段反复开工、重复全量回归和重复外审，让实现者在架构边界内连续完成可验收的垂直能力。

## 1. 要解决的问题

原计划把 M2.1、M2.2、M2.3 等每个子 ticket 都当成独立开工和外审点。这样虽然保守，但容易产生三类浪费：

1. 同一基础设施在相邻 ticket 反复改接口，例如 EnginePort、Coordinator、snapshot、Job 和 migration 必须一起才能证明完整价值；
2. 每个小 ticket 都重复跑全量回归、制作交接和等待外审，吞掉实现时间；
3. 局部实现先被冻结，后续模块才暴露跨模块问题，造成兼容层和文档返修。

新的原则不是降低验证强度，而是把验证从“频繁人工停工”改为“波次内自动检查、波次末组合验收”。

## 2. 四个垂直开发波次

| 波次 | 连续实现范围 | 垂直结果 | 正式审核次数 |
|---|---|---|---|
| Wave 1 受控运行时 | M2.1 + M2.2 + M2.3 | OpenFilm 受控写入、持久任务、snapshot、三类锁、迁移副本与真实回退 | 开工前一次；波次末内审一次、独立外审一次 |
| Wave 2 可编辑采用 | M3 + M4A/B/C | 提案绑定→真实 proxy/native plan→impact→采用→恢复→双导出 | 波次末内审一次、独立外审一次 |
| Wave 3 P0 产品闭环 | M5A/B/C + M6.1/2/3 | 同页 Studio、真实章节、性能/可访问、标题封面、发布检查、P0 交付 | 自动技术审查一次；用户体验/独立终审一次 |
| Wave 4 P1 完整 V1 | M7A/B/C/D | StyleProfile、声音字幕、provider/预算/反馈、完整长片 | 波次末完整 V1 审核一次 |

原 Mx.y 编号仍作为需求、提交、证据和故障定位单元，但不再默认成为等待人工批准的停工点。

## 3. 波次内连续推进规则

Claude Code 在一个波次内可以自动从模块 A 推进到模块 B，前提是：

- 模块合同测试和受影响回归通过；
- 没有违反 `06_ARCHITECTURE_CONTRACT_LOCK.md`；
- 没有未解决的 BLOCKER/MAJOR；
- 没有需要付费、外传、破坏性操作、可见窗口或人工内容判断；
- 前一模块证据已落盘，但不要求先做一次独立外审。

模块检查点只需要：增量测试、受影响回归、架构 fitness、证据追加和简短内部检视。全量回归、完整 HTML 报告、冻结 commit 和独立外审集中到波次末。

## 4. 返工抑制机制

### 4.1 一次冻结跨模块接口

Wave 1 开工前同时冻结 EnginePort、EngineBinding、TypedEdit、SourceDigest、SnapshotRef、CommitRecord、Lock、Job/Event/Lease、MigrationReport 的接口和状态机。M2.1 不再设计一个随后会被 M2.2 推翻的临时接口。

Wave 2 开工前同时冻结 ProposalBinding、Materialization、NativePlan、Impact、Adoption 和 History 的数据流。M3 的产物必须天然可供 M4 采用，禁止先交付只能播放、不能采用的死胡同。

### 4.2 垂直切片优先

每个波次先完成一条最窄真实链，再扩展负向矩阵。例如 Wave 1 先让一个固定 OpenFilm fixture 完成受控 inspect→stage→snapshot→commit→restart→rollback，再补齐所有 native 入口、并发和故障边界。

### 4.3 组合 commit 才是审核对象

模块提交用于定位和回退；正式结论绑定波次组合 commit。分支各自通过不能替代组合树回归。

### 4.4 失败聚类修复

同一根因造成的失败集中修复并一次重跑相关 case，不为每个失败分别制作全套报告。只有触及架构契约、持久格式或用户体验承诺时才回到文档层。

## 5. 仍然必须立即停止的情况

- 同项目双写、第二份可写 timeline、adapter 自主 commit；
- stale base 被 native rebase 绕过；
- commit/snapshot 不确定、数据损坏或回退不可验证；
- 未授权费用、外传、凭据或私有素材风险；
- 真实 Gate 连续两轮没有减少失败数量，说明路线而非实现细节可能错误；
- 需要用户提供真实内容、授权、人工体验或高风险选择；
- 服务器 422/429/529 等外部限制使真实验证无法继续。

普通单元失败、类型错误、局部回归和可修复的 adapter 差异不应触发人工停工；Claude Code 应在波次范围内自动修复并复验。

## 6. 审核压缩但不降级

每个波次只保留三类正式审查：

1. 开工前契约/计划审查：确认整波范围、接口和出门条件；
2. 波次末内部组合审查：架构、代码、体验、测试四个视角一次完成；
3. 波次末独立外审：绑定冻结组合 commit，复跑关键 Gate。

模块级检查由自动化流水线完成，不重复要求独立 Agent 审查。修复若未改变冻结架构和持久合同，只重跑受影响 case + 波次 smoke；若改变架构契约，才重新进行整波外审。

## 7. 成功指标

- 正式人工/外部审核从十余个小停点压缩为四个波次 Gate；
- 每个波次交付一个用户或系统可真实验证的垂直结果；
- 同一接口不在相邻模块反复重命名或重建；
- 全量回归只在波次候选、架构契约变化和最终修复后运行；
- 仍保持逐 case 证据、旧回归、真实素材/重启/导出和独立审查。
