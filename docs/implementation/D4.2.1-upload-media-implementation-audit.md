# D4.2.1 流式上传与媒体验证实现审计

## 1. 子阶段范围

本次只完成 D4.2.1 第 5 步的输入边界：固定 multipart 依赖、工程内私有 staging、流式 SHA、严格 part/长度限制、真实 ffprobe/ffmpeg 验证及依赖许可证/供应链证据。尚未接入 ImportService、内容寻址安装、GET/POST assets route 或 UI，不能声称用户导入已可用。

## 2. 已实现事实

- `busboy@1.6.0` 与 `@types/busboy@1.5.5` 精确锁定；不自研 boundary parser。
- 只接受各一个 `metadata` 与 `file` part；metadata 必须为 `application/json` 且不超过 16 KiB，file 必须为 `video/mp4`；重复、未知、缺失和超限 part 均拒绝。
- Content-Length 做严格十进制与 envelope 早拒绝；缺失时只接受 chunked；原始 request 与 file stream 双重计数。文件通过 pipeline 写入 Host 生成的工程 staging 私有目录，同时计算 SHA-256；失败清理本事务目录。
- staging 的每层目录均拒绝 symlink/非目录并在 realpath 后复核 containment；filename 不用于路径或返回值。
- ffprobe 使用 argv 数组验证 MP4、恰好一个视频流、`avg_frame_rate == r_frame_rate == project fps`、正帧数和尺寸；ffmpeg 通过 `vfrdet` 对视频流做完整 decode scan并要求变帧间隔计数为 0；最后重读并重新哈希临时文件。
- 内容不合格映射 422 `INVALID_MEDIA`；工具缺失、不可执行、超时、signal 或 stderr 超限映射 503 `MEDIA_TOOL_UNAVAILABLE`。
- 生产依赖审计曾发现既有 AJV 中危公告；虽未启用触发选项，仍精确升级到修复版 `8.18.0`。复审为 `No known vulnerabilities found`。

## 3. 内部验证

- 新增 9 项真实测试：合法 multipart/哈希、未知/重复/错误 MIME/超限/畸形 body/cleanup、envelope 早拒绝、chunked 原始流超限无挂起、symlink staging 拒绝、真实 300 帧 MP4 probe+decode+rehash、真实 VFR、错误帧率/损坏媒体、缺失工具。
- 全量 `pnpm check`：14 个测试文件、109/109，TypeScript 和 Vite production build 通过；`pnpm audit --prod --audit-level high` 为 0 已知漏洞。
- 已确认测试不产生 unhandled stream error；拒绝路径的 staging 为空。

## 4. 独立审查闭环

Claude Code CLI 首轮流式上传审查为 `PASS / critical=0 / major=0`，仅记录受控 0700 staging 下的剩余 TOCTOU、双 data listener 和 envelope 常量等非阻塞观察。媒体验证首轮指出只比较 `avg_frame_rate/r_frame_rate` 不能绝对证明 CFR；实现随即增加完整 decode 路径上的 `vfrdet`，并加入真实 VFR 文件测试。复审结论：

```text
VERDICT PASS
ALLOW_IMPORT_SERVICE YES
CRITICAL 0
MAJOR 0
MINOR 1
```

唯一剩余 minor 是最终哈希错误文案无法区分“调用方传入旧 SHA”和“验证中变更”；不影响拒绝结果。ImportService 仍必须将随机 0700 staging 中的同一已验证文件原子安装并在提交边界复核 SHA。
