## 2. 已实现事实

- 读取时执行 runtime schema 与语义校验：重复 asset ID、同一路径映射矛盾 SHA 均拒绝。
- 新 identity 严格等于 `asset_ + sha256(canonical_json({bytes_sha256,source,license}))`；canonical key 比较不依赖 locale。
- 新路径严格为 `media/<bytes_sha256>/source.mp4`；相同 bytes、不同许可得到不同 identity 并共享内容路径。
- @1 精确重复不迁移；首次新 identity 保留所有旧 entry 值与顺序并生成唯一 @2 canonical bytes + LF。
- publish 在写前复核 expected manifest SHA，使用同目录私有 `wx` temp、file fsync、rename、directory fsync 和 readback；restore 同样要求 expected current SHA。rename 后无法证明持久化时抛出带目标 SHA 的 `AssetManifestPublishUncertain`，供恢复器按实际落盘 SHA 裁决。
- 移除 `AssetRegistry.list()` 的跨请求缓存；manifest 与媒体 SHA 每次重读。
- `asset_import_journal` 保存 project/key、canonical request SHA、状态、asset/bytes SHA、before/after manifest SHA 与完整 preimage/after JSON、bytes_created、响应 status/body、错误码和时间。
- 状态严格为 `prepared → bytes_installed → manifest_published → committed`；跳步被拒绝。`aborted/compensated/attention` 为独立终态/恢复态。
- committed 幂等请求返回持久化的相同 status/body；同 key 异 hash 返回 409。journal 跨重启可枚举，attention 与 edit journal 共同阻断后续写；全过程不修改影片 revision。
