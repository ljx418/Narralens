# D4.1 多提案比较——开发及验收计划

版本：v1.0（2026-10-13，外审首轮问题修订）
状态：文档门禁通过；内部复审 PASS，Claude Code CLI 第二轮外审 17/17 CLOSED，允许进入 D4.1 实现

## 1. 单一阶段目标

D4.1 只实现“同一真实选区的一次请求，产生并比较 3–6 个结构不同的真实导演提案”。用户在当前统一工作台选择一个已登记镜头、输入导演意图、选择保留旁白/总时长并指定 3–6 个方案后，Narralens 通过现有受控 Claude Code CLI Runner 获得一个严格结构化的候选集合，由 Host 绑定当前项目、revision 与选区并原子暂存，最后在 `ProposalCompare` 中展示方案结构、素材需求、来源引用、真实生成费用状态和差异。

D4.1 是严格只读阶段：不得调用 `ProjectWriteActor`，不得调用 Hypit mutation，不得生成或下载视频素材，不得把研究来源当作素材许可，不得修改 Author Source、Run、旁白或 revision。D4.2 才实现“只素材化并采用用户选中的一个方案”。D4.1 通过只能把 P0-06 推进为“多提案比较已实现”，不能关闭 P0-08、P0-10、完整 D4 或 V1。

## 3. 冻结范围与非目标

### 3.1 本阶段必须交付

1. `proposal_count` 为 3–6 的请求契约，默认 UI 选择 3。
2. 单次受控 Runner 调用返回恰好请求数量的候选草稿。
3. Host 对全部候选执行 schema、绑定、帧数、引用完整性和结构差异校验。
4. Host 生成受信任 `comparison_id`、`proposal_id`、项目/revision/选区绑定及真实 Runner 审计字段。
5. 比较结果全有或全无地原子暂存；任一候选无效时整个任务失败。
6. `ProposalCompare` 同页展示 3–6 个可选择方案，并提供结构、分段、素材需求、来源引用、费用状态和差异摘要。
7. 422、529、取消、超时、Runner 不可用、旧 revision、晚到结果与用户手动重试体验。
8. 自动与真实 E2E 证明 Hypit Source、Run、旁白 SHA 和 Narralens revision 全部不变。

### 3.2 明确不做

- 不实现 `/materialize`、素材检索、素材生成、下载、审批或外传。
- 不把 Proposal 转成 edit operation，不写 Hypit，不刷新 build。
- 不实现旁白/时长主动写锁、历史恢复或持久任务恢复。
- 不声称方案已经可渲染；D4.1 输出固定 `requires_materialization=true`、`renderable=false`。
- 不把模型自报费用、模型名、project ID、revision 或 proposal ID 当成事实。
- 不自动重试 422、529、超时或失败任务；保留用户草稿并显式提供手动重试。

## 4. 冻结契约

### 4.1 请求

审查 schema：`docs/contracts/d4.1-proposal-request.schema.json`。

```json
{
  "base_revision": 2,
  "selection": {
    "shot_id": "shot-002",
    "start_frame": 300,
    "end_frame_exclusive": 600
  },
  "intent": "改成三镜递进组接，保留原解说，不改变总时长。",
  "preserve": ["narration", "duration"],
  "proposal_count": 3
}
```

`visual` 不属于本请求的 `preserve` 枚举；画面锁不阻止用户做只读提案比较，但任何后续采用仍必须在 D4.2 重新检查锁。D4.1 将当前 DirectorPane 的“原画面”伪 preserve 按钮从提案控件中移除，实际 visual lock 继续由项目锁状态和写事务负责，不能把两者混为一谈。UI 将中文选择显式映射为 `narration/duration`，不能把“旁白/总时长”原文直接发给 API。选区必须与当前 descriptor 中一个完整 registered shot 精确一致；`validateProposalComparisonRequest` 必须复用现有 `rangeErrors`，使 `end_frame_exclusive <= start_frame` 返回 400 且 0 次 Runner。D4.1 不扩大为跨镜选区。

### 4.2 Runner 草稿

审查 schema：`docs/contracts/d4.1-proposal-comparison-draft.schema.json`。

Runner 只能输出：

- `kind=narralens.proposal_comparison_draft`；
- 恰好 `proposal_count` 个候选；
- 每个候选的标题、策略、理由、分段、素材需求和来源引用；
- `requires_materialization=true`、`renderable=false`。

Runner 不输出 project/revision/selection、comparison/proposal ID、生成费用、模型、耗时和 CLI 审计。上述字段均由 Host 从受信任上下文或 CLI wrapper 生成，防止模型伪造。

Claude Code CLI 的 `--json-schema` 输入不能复用当前会丢弃约束的 `structuralSchema()`。D4.1 新增并单测 `inlineProviderSchema()`：只解析本地同一 schema 文档内的 `#/$defs/...`，递归展开所有 `$ref`，拒绝循环/外部 ref，保留 `type/required/properties/items/additionalProperties/minItems/maxItems/minLength/maxLength/pattern/enum/const/minimum/maximum/uniqueItems`。传给 CLI 前必须断言输出中不存在 `$ref/$defs`，根和每层 object 的 `additionalProperties=false` 仍存在，`proposals.minItems=3/maxItems=6` 及 strategy enum、两个 const 均未丢失；任何不支持关键字直接使 Host 启动/任务失败，不允许静默放宽。

### 4.3 Host 存储与 API 响应

审查 schema：`docs/contracts/d4.1-proposal-comparison.schema.json`。

Host 创建：

- `comparison_id=comparison_<uuid>`；
- `proposal_id=proposal_<comparison短ID>_<顺序>`；
- 当前 `project_id/base_revision/selection/preserve/proposal_count`；
- `intent_sha256`，暂存结果不重复保存用户原始导演文本；
- CLI wrapper 中的 `stdout_sha256/model_names/total_cost_usd/duration_ms/num_turns/service_tier`；
- 每个候选的 `materialization_cost={status:"unknown",currency:null,amount:null}`；模型不能自报后续素材费用，D4.2 获得 provider 报价前保持未知；
- Host 当前时间 `created_at`。

API 调整：

| API/类型 | D4.1 变化 |
|---|---|
| `POST /api/projects/:id/proposals` | request 增加必需 `proposal_count`，成功仍返回 202 Job |
| `JobResponse` / `JobEvent` | 成功结果增加 `comparison_id`；旧 `proposal_id` 仅作为 D2 向后兼容字段，不再用于 D4.1 成功结果 |
| `GET /api/proposal-comparisons/:comparisonId` | 返回完整、已校验的 `ProposalComparison` |
| `GET /api/proposals/:proposalId` | 保留读取 D2 历史单提案，不用它拼装 D4.1 比较结果 |
| `POST /api/jobs/:jobId/cancel` | 保持尽力取消；真实完成则 `completed_after_cancel` 并如实保留结果和费用 |

比较文件以 `comparison_id` 为文件名，禁止逐候选保存造成半套结果。`ProposalComparisonAdapter` 的发布顺序固定为：同目录以 `open("wx", 0o600)` 创建唯一临时文件 → 完整写入 canonical JSON → `FileHandle.datasync()` → close → 同文件系统 `rename()` 到最终名；POSIX 可用时再同步父目录，Windows 不支持父目录同步时如实记录限制。启动时只删除符合 Host 私有命名空间且未 rename 的陈旧临时文件，最终文件每次读取都重新做 JSON/schema/语义校验；损坏 final 返回稳定失败而非部分结果。这里承诺的是“原子可见、不会读取半套 comparison”，不是 D5 级掉电持久任务恢复。

目录和 ID 均由 Host 生成，API 不接受路径；`GET /api/proposal-comparisons/:comparisonId` 路由层仍须以 `^comparison_[A-Za-z0-9_-]+$` 二次校验，不能只依赖存储 schema。

## 5. 结构差异与语义校验

schema 通过只是第一层。`ProposalComparisonAdapter` 必须执行以下全部语义校验：

1. 候选数量严格等于请求 `proposal_count`，范围为 3–6。
2. `option_key`、`strategy.kind`、Host 生成后的 `proposal_id` 均唯一。
3. 每个候选所有 `segments.duration_frames` 之和严格等于选区帧数。
4. 每个候选内部 `segment_id`、`requirement_id`、`ref_id` 唯一；同一 comparison 内的 `option_key` 与策略也必须唯一。
5. 每个 `asset_requirement_id` 必须引用同候选 `assets_needed` 中存在的 requirement；不允许悬空引用。
6. `assets_needed.duration_frames` 不得超过选区帧数；累计可大于选区帧数，因为多个候选素材可能叠用，但 UI 必须按候选展示，不能伪装为最终时间轴。
7. 所有候选固定 `requires_materialization=true` 且 `renderable=false`。Host 为最终对象注入 `materialization_cost=unknown`；Runner 草稿不能提供或覆盖费用事实。
8. 两个候选除 `strategy.kind` 不同外，还必须至少满足一项结构差异：segment 数不同、role 序列不同，或整数 duration 向量不同。duration 签名将每个候选的帧数向量除以该向量全部元素的最大公约数（GCD），例如 `[100,200]→[1,2]`、`[150,150]→[1,1]`；禁止浮点百分比或 10% 桶，1 帧至长选区均使用同一确定算法。
9. 若任意一对候选不满足结构差异，整个结果返回 `422 INVALID_PROPOSAL_SET`，不展示“换标题但结构相同”的伪多方案。
10. D4.1 当前没有 P0-01 的受信任研究资料清单，因此 `RunnerInput.fixed_context.allowed_source_refs` 固定由 Host 注入空数组，浏览器不能提交；任何非空输出 `source_refs` 都使整套 422。真实 D4.1 UI 必须显示“项目尚未提供事实来源”，不能展示模型虚构引用。P0-01 后续阶段引入受信任来源 manifest 时，另立契约与审查，不在 D4.1 预留模糊读取路径。
11. 输出字符串总字节、候选/segment/asset/source 数量必须受 schema 与 Runner 1 MiB 总输出限制共同约束。

“结构不同”是机器门限，不替代人工叙事判断。真实阶段验收还必须由人检查至少三案确实代表不同讲述路径，而不是仅改变枚举或分段数量。

## 6. 状态机、并发与取消

单个 Job 状态仍为：

```text
queued → running → succeeded
                 ↘ failed
queued/running → cancel_requested → cancelled
                              └──→ completed_after_cancel
```

规则：

- Host 在创建任务前校验当前 revision 和 registered shot。
- Runner 返回后、原子发布 comparison 前，Host 重新读取当前 revision；若此时已经变化，任务以 `409 REVISION_CONFLICT` 失败。由于文件发布与 SQLite revision 不能形成跨资源原子事务，读取 comparison 和 D4.2 后续采用时仍必须再次比较 `base_revision`；检查后的极窄竞态只会留下不可采用的 stale 暂存对象，不能导致工程写入。
- 生成期间 Hypit Source/Run 不参与写入，但真实 E2E 仍记录前后 SHA，防止意外旁路写入。
- UI 使用 `useRef<number>` 维护 generation token；每次 `submit()` 先递增并捕获 `generation` 与 `jobId`。SSE 事件、comparison fetch、catch/finally 在每次 `setState` 前同时验证 `generation === generationRef.current` 且事件 `job_id` 等于该 effect 捕获的 jobId；cleanup 先使该 generation 失效。A 取消后立即提交 B、A 再晚到 succeeded/completed_after_cancel 时不得修改 B 的状态或 comparison。
- 用户取消后 Runner 若确认停止，状态为 `cancelled`；若 provider 已完成且结果通过全部校验，状态为 `completed_after_cancel`，UI 显示“取消后仍完成”及真实费用，不伪称免费或已取消。
- D4.1 不增加任务持久化；Host 重启后 D4.1 任务丢失必须如实显示。持久任务恢复继续属于 D5。
- `NarralensHost` 增加每实例、非 API 暴露的只读 diagnostics 计数：进入 `ProjectWriteActor.execute` 前递增 `write_actor_execute_count`。测试与真实 E2E 在 D4.1 全路径结束时读取/输出该进程内计数并断言为 0；不用全局静态状态，也不向浏览器暴露调试接口。

## 7. 错误语义

| 场景 | HTTP/任务错误 | 用户体验与不变量 |
|---|---|---|
| 非法请求、数量不在 3–6 | 400 `INVALID_REQUEST` | 保留导演意图；0 次 Runner 调用 |
| 请求时或完成检查时 revision 变化 | 409 `REVISION_CONFLICT` | 要求刷新项目；已检测到时不发布；任何竞态 stale 对象在读取/采用时再次 409 |
| Runner schema/数量/结构差异/引用失败 | 422 `INVALID_PROPOSAL_SET` | 全有或全无；不展示部分候选 |
| provider 权威 422 | 422 `PROVIDER_REJECTED` | 不自动重试，保留草稿 |
| provider 529/overloaded | 529 `PROVIDER_OVERLOADED` | 不自动重试，提示稍后手动重试 |
| Runner 不存在/异常退出 | 503 `RUNNER_UNAVAILABLE` | 不生成假候选 |
| 超时 | 504 `RUNNER_TIMEOUT` | 尽力终止；费用未知则显示未知 |
| 用户取消 | 200 job 状态 | `cancelled` 或 `completed_after_cancel`，不伪造成功/退款 |
| 暂存原子写失败 | 500 `INTERNAL_ERROR` | 任务失败；不存在可读取的半套 comparison |

`ApiErrorCode` 增加 `INVALID_PROPOSAL_SET`。错误详情只允许候选索引、字段路径和稳定原因，不包含原始 stdout、完整用户 intent、绝对路径、凭据或 provider 内部响应正文。

## 8. UI 与交互验收设计

`ProposalCompare` 在当前 DirectorPane 下方替换单张 Proposal 卡：

1. 数量控件提供 3、4、5、6，默认 3，可键盘操作并具有明确 label。
2. 提交后保留 textarea 内容和保留项；按钮显示真实 queued/running/cancel 状态，不显示假百分比。
3. 成功后使用 tablist/radiogroup 语义切换方案；每个方案显示标题、策略、理由、segment 数、总帧数、素材需求数和来源引用数。
4. 选中方案的详情逐段显示 role、帧数、视觉意图和对应素材需求；缺许可只显示“待素材化/待审批”，不得显示“可用”。
5. 比较摘要显示与其他方案的结构差异依据：策略、segment 数、role 序列和时长分布。
6. 费用区只显示 Host 注入的真实 CLI 审计：实际 USD、未知或 unavailable；不显示模型生成的估算。
7. 页面固定显示“D4.1 仅比较，不写入 Source；采用与素材化尚未开放”。不得出现可点击的“采用”按钮。
8. 失败、529、取消和旧 revision 后焦点回到状态区或重试按钮；草稿与数量选择不丢失。
9. 360、768、1440、1920 宽度无横向溢出；200% 文本下比较内容不截断。核心提交、取消、方案切换和详情阅读可全键盘完成。
10. 提案 preserve 区只显示“保留旁白/保留总时长”；不显示可点击“锁原画面”。项目真实 visual lock 可作为独立只读状态展示，并明确“仍可比较，采用时会重新检查锁”。

## 9. 开发顺序

1. **D4.1.1 contracts**：新增生产 request/draft/comparison schema、TypeScript 类型、`rangeErrors` 语义和 AJV validator；同步 `ApiErrorCode` 与 `contracts/api-error.schema.json` 的 `INVALID_PROPOSAL_SET`；保留 D2 schema 回归。
2. **D4.1.2 Runner**：实现失败关闭的 `inlineProviderSchema()`，完整保留关键约束并以单次调用返回请求数量候选；`RunnerOutput` 同对象返回本次 wrapper audit，禁止用可能串 Job 的外部回调拼接；保留 422/529/超时/大小限制。
3. **D4.1.3 Adapter/staging**：GCD 结构差异、空来源白名单、Host ID/绑定/费用包装、`open→write→datasync→close→rename` 原子发布、启动清理与读取重校验。
4. **D4.1.4 Host/jobs**：`comparison_id`、路由 ID 二次校验、新读取 API、完成/读取 revision 复核、每实例 NOWRITE diagnostics、取消/晚到语义和稳定错误码。
5. **D4.1.5 UI**：数量选择、移除提案“原画面”伪锁、中文 preserve 映射、generation token、3–6 方案比较、详情、真实费用/来源状态、键盘与响应式交互。
6. **D4.1.6 自动化测试**：contract、adapter、runner、Host HTTP、UI、回归和 NOWRITE 测试。
7. **D4.1.7 真实 E2E**：真实 Claude Code CLI 生成 3 个方案；Headless 浏览器提交、切换、取消/529；记录 Source/Run/旁白/revision 不变。
8. **D4.1.8 审计与出门**：证据 manifest、PRD/架构/追踪矩阵同步、内部实现审计和 Claude Code CLI 外部实现审查。
