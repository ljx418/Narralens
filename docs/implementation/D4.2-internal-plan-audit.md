## 5. 架构与事务审查

- 唯一最终影片事实源仍为 Hypit Source + Run。MaterializedProposal 不能独立渲染，删除它不改变已采用影片。
- UI 只提交文件 bytes、受限元数据、ID 和 approval；不提交本机路径、segment 可执行计划或 Source patch。
- Asset import、manifest 原子写和 Source 写共享每项目串行边界；影片 revision 只在 Source transaction commit 后增加。
- composite 安装顺序为私有 staging → 完整 decode/ffprobe → content-addressed bytes → v2 manifest → materialization record。中途崩溃最多留下不可见或未引用 bytes，不能留下 record 指向不存在资产。
- adopt 顺序是 current impact/revision/lock/entry/bytes 校验 → journal prepare → Studio expected manifest SHA + Source preimage → typed replace → postcondition → metadata commit。
- Hypit fork只扩展 manifest 解析/安全重载，不扩展视觉拓扑；如果实现事实要求正则写 Source 或放宽路径/许可，计划明确 NO-GO。

## 6. 契约与测试充分性

- 五份 schema 均以 AJV strict 2020 模式编译通过；derived 缺 lineage 被拒绝，非 derived 携带 lineage 被拒绝，restricted 条目可登记。
- schema 之外的跨字段语义均在计划中列为 Host validator：segment 不重不漏、输出范围连续、总帧数、引用条目不变、许可、impact SHA。
- 测试矩阵覆盖合同、上传中断/大小/MIME/CFR、许可、Job 取消/晚到、deterministic composite、manifest reload、采用、审批、锁、revision、TOCTOU、补偿、崩溃恢复、幂等、UI/a11y/security、旧阶段回归和真实 E2E。
- 真值证据同时要求 Source/Run/narration/revision/semantic、ffprobe、边界帧、journal 和浏览器行为；截图不能单独证明成功。

## 7. 剩余风险（已设门禁，非文档阻塞）

1. Windows/WSL 上 libx264 同参数双跑是否 byte-exact 仍需 D4.2.2 真实探针；不一致必须停下修改“确定性”模型并重新外审。
2. Hypit @2 manifest 动态重载可能触及启动时缓存假设；已前移为 D4.2.1 导入能力的同批前置，须先完成 fork 单元/集成/真实 Studio 与 D4.0 回归，不能先开放导入 UI 或写 Narralens adopt UI。
3. 2 GiB 上传的 backpressure、客户端中断和磁盘不足须用真实大文件/故障注入验证；单元 mock 不足以出门。
4. AssetManifest 256 项上限可能在长期项目中不足；本阶段明确容量耗尽 422，不以未设计垃圾回收扩大范围。

这些风险均有明确子阶段、失败门限和退回动作，不需要当前用户路线选择。

## 9. Claude Code CLI 外审首轮闭环

首轮机器结论为 `EXTERNAL_DOCUMENT_REVIEW=PASS`、`ALLOW_D4_2_IMPLEMENTATION=NO`、fatal 0、major 2、must-fix 3。逐项处理：

| 外审项 | 独立复核 | 处理 |
|---|---|---|
| MAJ-1 derived 未在 schema 强制 cleared/commercial | 有效 | v2 schema 增加 derived → cleared + commercial=true；计划增加双层 Host 语义校验与 D42-MANIFEST-02 |
| MAJ-2 generated + cleared 被判冲突 | 无效 | `generated` 是 synthetic 事实，`cleared` 是许可就绪，二者正交；禁止组合会偏离 PRD。主架构、UX 和 D42-SYNTHETIC-01 已明确 synthetic 必须显示且不得冒充现场 |
| MUST-1 lineage `not` 可能失效 | 原实现已通过本机 AJV 正反例，但表达可简化 | 改为互斥 `oneOf`：derived 必须 lineage，owned/generated/licensed 无 lineage 字段；再次严格 AJV 验证 |
| MUST-2 multipart policy 缺 schema 锚点 | 有效，但自定义 `x-*` 会被生产 AJV strict 拒绝 | 使用标准 `$comment` 记录 envelope，Host parser 才是强制层；计划补齐 part/stream/413/backpressure/磁盘满测试 |
| MUST-3 restricted + commercial=true 被判非法 | 部分无效 | `restricted` 可表示允许商业使用但仍受归属/地域/期限限制，必须允许登记但禁止采用；schema 只强制 `cleared → commercial=true`，测试同时证明 restricted+true 可登记、materialize 422 |

本轮严格 AJV 2020 复核已证明：derived+lineage+cleared 通过；derived 缺 lineage、derived+restricted、non-derived+lineage、cleared+commercial=false 均拒绝；restricted+commercial=true 可登记。该语义与“只有 cleared && commercial_use 才能采用”一致，不以过度收窄库存合同换取表面通过。
