## 1. 实现范围

- `HostApiClient` 新增完整库存读取和可取消导入；浏览器 wire body 由 `new Blob([metadata headers, metadata JSON, file headers, original File, trailer])` 组合，引用原始 File 而不调用 `arrayBuffer()`/`text()` 读取完整媒体到 JavaScript 内存；客户端 wire 与 Busboy 的交叉测试冻结这一合同。
- multipart 固定为一个 `application/json` metadata field 和一个 `video/mp4` file part；客户端不提交本机路径，wire filename 固定为 `upload.mp4`。
- 独立 `AssetLibrary` 提供本地文件选择、来源/许可表单、真实“上传中 → 媒体校验与登记中”状态、取消、错误焦点、成功后库存与 D4.0 eligible 列表刷新。
- 公开库存显示 available/eligible、许可阻断和 generated 标志，不显示 `project_path`、绝对路径或 token；页面明确“已登记，未进入时间轴”。
- 360/768/1440/1920 响应式布局和深色主题无头 Chrome 截图已生成；另有 2x device-scale 渲染截图，但它不替代最终真实 200% text zoom 验收；axe critical/serious 为 0。
- 可重复 `pnpm evidence:d421-large` 使用合法顶层 `free` atom 把已验证 MP4 扩展到精确 64 MiB，仍经 ffprobe/ffmpeg 完整解码；脚本再以 32 MiB 上限验证 413 和 staging 清理。

## 2. 内部独立审查与修复

内审发现并闭环：

1. 原始方案使用 `FormData.append(metadata, Blob(application/json))`，真实浏览器会把 metadata 编码成 file part，与 Busboy 的 field 合同冲突。现改为复合 Blob 严格编码两个 part，并增加客户端 wire → 服务端 parser 交叉测试。
2. 原始成功路径把导入响应、库存刷新、项目刷新放在同一 `try`；导入已提交但刷新失败时可能显示“导入未完成”。现以导入响应作为提交边界，刷新失败只显示“需要刷新”，不否认已提交事实。
3. 旧 UI 测试夹具未实现库存 API，产生 happy-dom 网络中止噪声。现使用完整类型库存夹具，测试输出干净。
4. 上传文件精确等于上限曾因 Busboy limit 事件语义被误拒；生产限制采用业务上限加一后显式字节判断，精确上限 200、超过一字节 413。
