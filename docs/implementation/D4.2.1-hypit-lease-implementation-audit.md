## 2. 已实现事实

1. Hypit `media.replace` 要求 64 位小写 `manifestSha256`；缺失或格式错误在 HTTP 边界返回 400，SHA 不匹配返回 409。
2. lease 使用一次完整重读形成不可变 entries；目标 `resolve` 只接受 cleared/commercial，`identifyLocator` 仍可识别 restricted/unknown 的既有绑定。
3. 清单复核覆盖 lease 获取、patch planning 的敏感读取、Source apply 前、Source apply 后/publish 前、成功响应前；写后漂移会恢复 Source preimage 并重新 publish。
4. Studio 普通 snapshot 使用当前 manifest view，不再把启动 entries 当作永久权威；Hypit 不写 manifest 或媒体 bytes。
5. Host 只有在 `inspectMedia` 证明 Source 与写前完全一致时，把上游 manifest conflict 映射为 409 `MANIFEST_CHANGED`；无法证明恢复则进入 423 attention；普通 Source 409 保持 `REVISION_CONFLICT`。
6. Hypit parser 的 `asset_id`、@1 cleared/non-commercial 可读语义、@2 derived/lineage/许可约束已与 runtime schema 对齐；不可采用条目仍不能成为 mutation target。
