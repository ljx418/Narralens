# D4.0 类型化媒体替换——开发及验收计划

版本：v1.0（2026-10-12）  
状态：已通过；路线 A 实现与内外实现审查已闭环，Hypit fork/gitlink 固定为 `ljx418/hypit@437563f977541002066e6ee961f83a67cbebd3c2`

## 1. 单一阶段目标

D4.0 只关闭一个技术前置能力：用户从已登记且许可状态可用的本地视频资产中选择一个 `asset_id`，Narralens 经现有单工程写入 actor 调用 Hypit Studio 新增的类型化 `media.replace` mutation，使真实 `d1-30s` 工程的 `shot-002` 独立改用该资产；非目标镜头、旁白、时长和 Run 定义不变。修改需经重编译、关闭重开、`check/plan/build` 和第二次正常 mutation 恢复精确基线证明。

D4.0 不生成 3–6 个 Proposal，不调用付费或联网素材 Provider，不把当前 D2 Proposal 标记为 renderable，不关闭完整 P0-06/P0-08。D4.1 才冻结多提案比较，D4.2 才冻结“只素材化选中方案”的采用链。

## 2. 事实基线与路线约束

- Narralens Gate D1–D3 已通过；当前 Hypit 固定于 `85e01c76716498e6ec5b8bdfb6b374ca67f0195a`。
- 当前 Hypit `StudioMutation` 只有 `timeline.adjust` 与 `parameter.adjust`；路线 A 授权在 Hypit fork 增加一个窄的 package-owned mutation，而不是让 Narralens 写 SVML。
- `d1-30s` 三个 visual clip 当前共用 `visual-media` / `visual-source`；直接改共享 `src` 会误伤三个镜头。
- Hypit Markup parser 已暴露结构化 element、attribute value range 与 reference；D4.0 复用它做受限结构编辑，不引入全文件 serializer，不用 regex 猜标签。
- 当前 Source 的可支持拓扑限定为：目标 `visual:Clip.media` → 本地 `mediaop:Normalize.media` → 本地 `media:Video.src`。其他拓扑必须 422，不能猜测。
- 资产 bytes 必须位于工程根内、具备清单登记和精确 SHA-256；API 请求不得携带路径、URL、Source 文本、tag 名或 attribute range。

## 3. 冻结外部契约

### 3.1 AssetManifest

工程根新增 `narralens.assets.json`，schema 为 `docs/contracts/d4-asset-manifest.schema.json`。`asset_id` 在单工程内唯一；`project_path` 只能是工程内相对路径；D4.0 执行策略只允许 `kind=video`、`media_type=video/mp4`、`license.status=cleared` 且 `commercial_use=true`。schema 中保留的 `restricted/unknown` 是未来导入和审批状态，不代表 D4.0 可采用，命中时明确返回 422。每项记录内容 SHA-256、真实 `duration_frames`、来源与许可标签。`source.uri` 仅是不可执行的来源元数据，不得由 Host/Studio 请求、下载或解析成编辑 locator。

Narralens 在 API 前验证 schema、许可、frame rate 下的时长下限和 SHA。Hypit Studio 通过显式 CLI 参数 `--asset-manifest <file>` 启动，并独立验证清单格式、ID 唯一、realpath 仍在 workspace、文件 SHA 与清单一致；每次 prepare/mutation 都重新读取并校验 bytes SHA，不能只信启动时结果。Studio 冻结启动时 manifest SHA，运行中清单文件变化视为 409 外部变更并要求重启，不热接受新授权。清单只授予 asset bytes 读取和生成相对 locator 的能力，不扩大 Source import 根，也不允许网络 URI 作为编辑输入。

### 3.2 Narralens edit operation

`POST /api/projects/:id/edits` 保持 D3 envelope、selection、preserve、base revision、idempotency 和错误体，只把单 operation union 扩展为：

```json
{
  "op": "replace_visual_asset",
  "shot_id": "shot-002",
  "asset_id": "asset_d4_local_alt"
}
```

operation schema 为 `docs/contracts/d4-media-edit.schema.json`，完整 envelope schema 为 `docs/contracts/d4-edit-request.schema.json`，descriptor 的 manifest 登记见 `docs/contracts/d4-project-descriptor.schema.json`。本阶段仍要求恰好一个 operation、单镜精确 selection、`preserve` 同时含 narration/duration。客户端不能传 `project_path`、preimage、Source range 或 authored ID。

业务与上游协议使用不同且明确映射的词汇，不要求字符串相同：

| 边界 | 字段 | 值 | 说明 |
|---|---|---|---|
| UI → Narralens Host | `operation.op` | `replace_visual_asset` | 稳定业务意图，使用业务 `shot_id` |
| Descriptor → Adapter | `shot_id → authoring_id` | 如 `shot-002 → shot-2` | 已在 D3 冻结的身份映射 |
| Adapter → Hypit Studio | `mutation.type` | `media.replace` | fork 内部 typed mutation，使用当前 session `itemId` |

preimage 由 Hypit Studio 从当前 revision、AST attribute range 和磁盘 Source 计算并验证，绝不由不可信客户端提交。

### 3.3 Hypit Studio mutation

Hypit 内部 TypeScript union 增加：

```ts
{
  type: "media.replace";
  revision: number;
  itemId: string;
  assetId: string;
}
```

`itemId` 必须来自当前 session，服务端再校验它仍唯一对应一个 authored visual item；`assetId` 只能由启动时装载的 manifest 解析。成功保持现有 `{revision}` 响应。malformed body 为 400；Studio revision、Source preimage 或启动后 manifest SHA 变化为 409；未知/越界/资产 bytes 哈希不符/许可不可用/不支持拓扑/无法保证局部影响/编译或后置条件失败为 422；意外 I/O 为 500。Narralens 只把显式 409/422映射为稳定业务错误，响应丢失仍按 D3 attention 规则处理。统一错误码以 `03_Architecture.md` §7 为权威；生产 `contracts/api-error.schema.json` 在 D4.0.4 同步补齐现有 D3/D4 代码枚举，不能继续落后于 TypeScript union。

`GET /__studio/session` 的 visual item 增加可选只读字段 `mediaAsset: {assetId, sha256}`。它只在当前 binding 能唯一解析到启动清单中的资产时出现，不暴露 locator、相对/绝对路径或 Source range。D4.0 的 before/after、补偿和恢复只使用该 opaque identity；字段缺失或不唯一时 prepare 返回 422。

## 4. Hypit package-owned MediaBindingEditor

新增编辑器必须从真实 author source 和 Markup AST 计算 patch，所有 patch 仍进入现有 `applyTransaction → publish/recompile → rollback` 路径。

算法固定如下：

1. 读取原始 Source 后先用 Hypit Source Header parser 生成保持 UTF-16 offset 的 masked text，再调用公开 Markup syntax parser；禁止把 `<?svml ...?>` 当普通 XML 跳过。随后从 snapshot item 取得 authored ID，在当前 author source AST 中唯一定位同 ID 的 `visual:Clip`；验证 `media` 是本地 reference。
2. 沿 reference 唯一解析到 `mediaop:Normalize`，再沿 `source` 唯一解析到 `media:Video`；读取准确 attribute ranges 和 element ranges。遇到 source import、动态表达式、多个定义、跨文件声明或未知 tag 均拒绝。
3. 将 manifest 的 project-relative file 转换为相对当前 author source 的 POSIX locator；再次确认 canonical file 在 workspace 内且 bytes SHA 匹配。
4. 若 Source 已存在使用同一 locator 且 normalization 属性与当前链兼容的 binding，目标 clip 只改为引用该 binding。
5. 若当前 binding 仅被目标链独占，直接只改对应 `media:Video.src`。
6. 若 binding 被其他 visual item 使用，则克隆当前 `media:Video` 与 `mediaop:Normalize` 两个完整结构 element，生成稳定且冲突检查后的 `hypit-media-<shot>-<sha12>` / `hypit-normalize-<shot>-<sha12>` ID；`<shot>` 是经 Hypit identifier 规则验证的 authored ID，`<sha12>` 是目标资产 bytes `sha256.slice(0,12)`。只改克隆的 `id/src/source`，插入同一 Source，并把目标 clip 重绑定到新 normalize。克隆/插入由 Hypit 编辑器拥有；Narralens 不获得 Source range。
7. 编辑器构建 Source 内所有结构化 reference 的反向索引。切换到既有 binding 时，只允许删除满足全部条件的旧 clone：ID 符合生成命名空间、element 结构与编辑器模板一致、asset SHA/shot 能从 ID 与 manifest 对应、反向引用计数为零、该 clone 对的插入 span/邻接空白有本次编辑器可重建的精确形态。任一条件不成立则拒绝本次“精确恢复”并 422，不得误删或悄悄保留后宣称恢复。D4.0 真实夹具必须达到 `alt → baseline` Source 字节与 SHA 完全一致。
8. mutation 生成 patch 前计算 consumer 集，重编译后再次比较：目标 authored item 的 media resource/hash 必须是目标资产；所有非目标 item 的 authored ID、帧范围、视觉 material identity 不变；timeline、旁白和 Run 不变。无法证明即回滚并 422。

“共享 consumer”本身不等于失败：编辑器能通过隔离 clone 保证局部影响时允许；只有无法隔离或后置影响超过目标时 422。

## 5. Narralens 事务扩展

| 实体 | D4.0 变更 |
|---|---|
| `ProjectCatalog` | 按 `d4-project-descriptor` 装载 descriptor 指向的 manifest，禁止 API 覆盖路径 |
| `AssetRegistry` | schema、许可、realpath、SHA、MIME、duration 校验；只返回 opaque asset record |
| `HypitWriteAdapter` | 从 session 的 opaque `mediaAsset` inspect 当前资产；提交 `media.replace`；不解析/预测 SVML |
| `ProjectWriteActor` | operation union 分发；journal 记录 before/target asset identity、manifest hash、semantic before/expected |
| `RevisionStore` | journal migration 保持旧 D3 记录可读；D4 字段可空或放入版本化 operation snapshot |
| `DirectorPane` | D4.0 只提供“当前素材→本地替代素材”的明确影响确认；不伪装成 Proposal compare |

事务沿用 D3 FIFO、base revision、visual lock、idempotency、attention 和补偿模型。区别是补偿调用新的 `media.replace` 指向 before `asset_id`；因此 D4.0 manifest 必须同时登记初始 `visual-10s.mp4` 与替代资产，若当前资产不是清单内可寻址对象，prepare 阶段就拒绝。`visual-10s.mp4` 是被三个 10 秒窗口重复引用的 10 秒源素材；工程总时长仍为 900 帧/30 秒。

journal 固定记录 manifest SHA：在创建 prepared journal 前发现 manifest 变化，事务不开始并返回 409；prepared 之后发现 manifest 或资产 bytes 变化，结果已无法仅靠客户端重试确定，转 attention。D4.0 增加显式的本机维护命令 `narralens recover <project>`：它只能在 Studio/manifest 恢复可读后复用同一三态判定，将确定 target 的记录 finalize、确定 before 的记录 abort，其余保持 attention；不存在“无证据 manual reset”。成功后的 Narralens revision 只增 1；no-op 不增 revision。

## 6. 安全与数据边界

- Studio 仍只接受本地同源 mutation；descriptor 仍只允许带端口的字面量 `127.0.0.1`。
- manifest 参数只能由本机启动命令提供，路径不得来自浏览器/API body；manifest 与 assets 的 realpath 都必须在 workspace。
- `asset_id` 正则、body 大小、清单条数和单项字符串长度设上限；重复 ID、symlink 逃逸、hash mismatch、未知媒体类型失败关闭。
- manifest、资产和 Source 的校验与使用都基于 canonical path/重新读取的 bytes；检测到 TOCTOU 变化即拒绝或 attention，不能继续使用陈旧 hash。
- 上限冻结为 manifest 文件 1 MiB、最多 256 个资产、任一 JSON 字符串 2 KiB；Studio mutation 响应仍受 Host 现有 4 MiB 上限约束。
- Source patch replacement 仅由 AST range、经过转义的引用/locator和受控 ID组成；不得拼入用户 Source 片段。
- evidence 与错误不得包含绝对路径、Source 正文、凭据或外部签名 URL。
- D4.0 本地替代资产必须由测试脚本在工程内生成并标记 `source.kind=generated`、许可 cleared；不访问网络，不产生费用。

## 7. 开发顺序

1. **D4.0.1 Hypit contract/registry**：mutation union、body validator、CLI manifest 参数、manifest loader/containment/hash tests。
2. **D4.0.2 Hypit MediaBindingEditor**：AST 拓扑解析、独占替换、共享 clone、既有 binding 复用、owned orphan cleanup、patch unit tests。
3. **D4.0.3 Hypit transaction integration**：接入 `mutationPatches` 和现有 rollback；真实 Studio integration 覆盖 stale/422/compile failure。
4. **D4.0.4 Narralens integration**：生产 contracts/types/validator、AssetRegistry、Adapter、actor/journal、API/UI；保留 D3 regression。
5. **D4.0.5 真实 E2E**：生成有明显视觉差异的本地 10 秒 MP4；`shot-002 baseline→alt`，重启 Studio/Host，check/plan/build，浏览器证据，再通过正常 mutation `alt→baseline`。
6. **D4.0.6 审计**：全量测试、PRD/架构检视、安全扫描、evidence manifest、内部实现审计和 Claude Code CLI 外审。

### 7.1 Hypit fork 与子模块交付策略

- 开发从当前 upstream base `85e01c76716498e6ec5b8bdfb6b374ca67f0195a` 建立 Narralens 专用 fork 分支；实现期间允许 `vendor/hypit` dirty，但每份证据必须记录 base SHA 与 `git diff --binary` SHA。
- D4.0 实现外审通过后，在 Hypit 子仓创建一个可复现 commit，再把主仓 submodule gitlink 更新到该 commit；主仓 `.gitmodules` 在同步前改为项目负责人可访问的 fork URL。无法推送或 clone 该 fork 时不得做阶段 Git 提交，也不得声称 pin 完成。
- 主仓只记录 gitlink，不复制 vendor 源码补丁；审计证据额外保存文本 diff 统计与 commit SHA，便于确认改动面。
- 许可证仍按当前本地单组织自用边界；对外分发/网络服务另行审查。

## 10. 出门与停止条件

以下全部满足才可声明 D4.0 通过：文档内外审无未关闭致命/重大；Hypit 与 Narralens 测试全绿；真实共享 binding 被安全隔离；重启与 build 成功；失败路径恢复；正常事务精确恢复 baseline；证据无泄漏。

若 Markup AST 无法可靠定位/编辑当前拓扑、clone 后无法证明非目标不变、Studio rollback 无法恢复、或恢复基线必须手工改文件/git checkout，则停止并回到路线决策，不进入 D4.1。D4.0 通过也只能把 P0-08 标为 partial，不得声明完整 D4 或 V1 完成。
