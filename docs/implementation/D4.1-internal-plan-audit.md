## 1. 审查边界与方法

本轮在 D4.1 计划初稿完成后重新从 PRD 和当前生产源码出发审查，不使用“文档已写完”作为通过依据。审查对象：

- `01_PRD.md`、`03_Architecture.md`、`04_Development_Plan.md`、`05_Acceptance_Plan.md`、`11_V1_Traceability.md`；
- `implementation/D4.1-development-and-acceptance-plan.md`；
- 三份 `docs/contracts/d4.1-*.schema.json`；
- `architecture/d4.1-multi-proposal-compare.architecture.json/html`；
- 当前 `ControlledAgentRunner`、`ProposalAdapter`、`JobStore`、Host API、UI、生产 contracts 和 D2–D4.0 测试。

独立检查维度为：PRD 覆盖、事实基线、信任边界、数据契约、结构差异、并发/取消、费用真实性、NOWRITE、安全、UI/无障碍、测试证据和阶段边界。

## 2. 审查结论

**内部结论：PASS，可进入外部文档审查；不可进入实现。**

计划已经把 D4.1 收敛为可独立验收的只读多提案阶段，并明确 D4.2 才负责素材化和采用。当前未发现未关闭致命或重大文档问题。生产代码、运行时 schema 和测试尚未修改；任何实现动作必须等待 Claude Code CLI 外审 PASS 且所有有效问题闭环。

## 4. 契约与架构核验

- 三份 review schema 均通过 AJV 2020 strict compile。
- request、Runner draft、Host final 正样例均通过。

- comparison 是全有或全无的一个原子文件，不通过逐 proposal 文件制造半成功。

- Draw.io 仍为 7 页且根结构完整；D4 节点已区分 D4.0 通过、D4.1 docs-only、D4.2 未开始。

## 6. 实现前必须由外审重点复核

1. Claude CLI `--json-schema` 是否能接受从 `$defs` 安全内联后的 3–6 候选 schema，且不会放宽 `additionalProperties`。
2. `RunnerOutput` 如何把同一次 wrapper 的 audit 与 draft 一起返回，防止回调丢失或串 Job。
3. completion revision 复核和 comparison 读取 409 是否足够阻止 stale 对象进入 D4.2。
4. UI generation token、SSE replay 和 `completed_after_cancel` 是否覆盖晚到结果覆盖新任务的风险。
5. 结构差异签名是否既可确定测试，又不会把叙事上相同的方案误判为不同。
6. 白名单为空时真实 Runner prompt 是否稳定返回空 `source_refs`，而不是虚构来源。
7. 原子 staging 的 fsync/rename 失败注入是否可在 Windows/WSL 当前文件系统重复验收。

## 7. 已知限制与门禁

- D4.1 仍只支持单一 registered shot，不覆盖跨镜选区。
- JobStore 仍为进程内；Host 重启后的任务恢复属于 D5。
- 当前阶段不产生素材、不接 provider、不采用提案、不写工程。
- 真实 provider 可能返回 422/529；按用户授权无客户端硬预算上限，但每次用户动作只调用一次且不自动重试。
- 机器差异规则不能替代人工导演判断，真实验收必须保留人工叙事差异结论。
