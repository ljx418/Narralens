## 1. 审查边界

本轮只审查 D4.2.1 已冻结计划中的扩展 fault/race 门禁，不重复宣称合同、Hypit lease、导入服务、UI 或大文件证据。审查对象是上传断连、文件系统故障、manifest 发布不确定性和同项目并发。真实浏览器交互、真实 200% 文本缩放及 D4.2.1 总审计仍不在本轮完成范围。

## 2. 内部独立审查结论

内部审查结论为 `PASS / critical=0 / major=0 / must-fix=0`，可以提交 Claude Code CLI 独立外审。门禁依据：

1. 故障入口只能通过进程内构造依赖注入，HTTP、环境变量和项目文件都不能选择故障点；生产构造路径继续使用 Node 原生 write stream、hard link、rename 与 fsync。
2. staging `ENOSPC` 和真实 chunked client disconnect 都经过真实 HTTP/request stream，最终私有 staging 为空。
3. content hard-link、manifest temp write、rename 在发布前失败时返回 500，manifest bytes、Author Source/Run/narration/revision 均不改变，新内容 bytes 被移除。
4. directory fsync 或发布后 readback 的一次性失败按“可能已发布”处理，使用精确 manifest preimage 补偿、重读证明恢复，再删除未引用的新内容；不得返回成功。
5. 补偿阶段持续无法证明目录持久性时返回 423 并持久化 project attention；即使当前读到的 manifest bytes 恰好等于 preimage，也不把“当前可读”冒充“持久性已证明”，新内容因此保留以避免破坏可能存在的引用。
6. 同一 project 的两个不同导入以及两个相同幂等请求均通过真实 HTTP 并发进入；共享 `ProjectOperationQueue` 防止 lost update，同 key 只增加一个条目且响应逐字段一致。
7. 全部新增路径断言 `ProjectWriteActor.execute_count=0` 或 Author facts 不变，导入不借机写 Source/revision。

## 3. 有意保留的架构边界

- `AssetRegistryDependencies`、`AssetUploadDependencies` 和 `AssetImportServiceOptions.contentInstall` 是窄接口测试缝，不是运行时插件系统；不从远端输入构造。
- `ProjectWriteActor` 可接收同一 `AssetRegistry` 实例，仅用于让测试装配满足 Host 对共享依赖身份的校验；默认生产调用不变。
- fault hook 位于真实 I/O 前后，测试没有替换事务编排、journal、HTTP normalization、补偿或 attention 判定。
- 客户端在上传过程中断可证明 staging 清理；在原子提交边界附近取消仍遵循 UI 已冻结语义：取消不能虚假承诺撤销已经提交的结果。
