## 4. 本轮发现并已闭环的问题

1. **原始 SVML 带 Source Header**：Markup syntax parser 接受的是保持 offset 的 masked text。计划已明确必须复用 Source Header parser/mask，不能用字符串查找跳过处理指令。
2. **补偿缺少当前媒体 identity**：既有 session 不公开媒体 binding。计划已冻结只读 opaque `mediaAsset {assetId, sha256}`，不暴露路径，使 Adapter 能确定 prepare/补偿/恢复。
3. **初始资产无法补偿**：只登记替代资产会导致 before 不可寻址。计划已要求 manifest 同时登记 baseline 与 alt。
4. **manifest/bytes TOCTOU**：只在启动时读 hash 不足。计划已要求启动冻结 manifest SHA、每次 mutation 重验 bytes，旧 journal 与新 manifest 不兼容时进入 attention。
5. **共享引用处理语义含混**：共享不应机械拒绝，也不能直接改共享 source。计划已明确“可隔离 clone 则允许；无法证明局部影响才 422”。
6. **恢复 baseline 可能只语义相等**：计划已把 D4.0 真实夹具门限提升为正常 mutation 后 Source SHA 精确恢复，不允许手工覆盖。

## 5. 实现前设计决策（首轮外审后全部冻结）

1. **clone/cleanup**：Hypit editor 基于 Markup AST element/attribute ranges 和完整反向 reference 索引生成 patch；只有生成命名空间、模板形态、manifest 身份、零反向引用和邻接 span 全部匹配才可清理，否则 422。真实夹具必须 clone→复用 baseline→Source SHA 精确复原。
2. **`mediaAsset` 投影**：由 Hypit `MediaBindingEditor` 的只读 projector 在 server publish 后计算并附到 `StudioItem`；只输出 manifest `assetId/sha256`，不输出 path、locator、range，未登记/歧义时省略字段，Host prepare 422。
3. **manifest 状态机**：prepared 前 manifest SHA 与启动 SHA 不同 → 409 且不建 journal；prepared 后 manifest/bytes 变化 → attention。恢复只能通过 `narralens recover` 在证据恢复后重判 before/target，不允许强清。
4. **错误映射**：planner 的受支持拒绝抛专用 `StudioMutationRejected` → 422；revision/preimage/manifest 外部变化 → 409；意外 I/O → 500；响应不确定由 Host 复读并按 D3 attention 处理。
5. **fork 交付**：以 upstream `85e01c...` 为 base；实现期间记录 dirty diff SHA；实现审计通过后在可访问的 Narralens fork 形成 commit，更新 `.gitmodules` URL 与主仓 gitlink。不能 clone/pin 时阶段 Git Gate 不通过。

## 7. Claude Code CLI 首轮外审裁决

首轮结论为 FAIL（报告原始计数：致命 8、重大 11、一般 10）。内部逐条对照源码后，未机械接受错误事实，也未因误报忽略有效风险。

### 已接受并修订

- 补充完整 D4 request envelope 与 descriptor schema；明确业务 `replace_visual_asset` 到 Hypit `media.replace` 的映射，客户端不得提供 preimage。
- 对齐 AssetRef/AssetManifest 字段、统一错误码表、PRD/D3 状态和 P0-07 partial 口径。
- 冻结 clone 引用图/清理条件、manifest 变化状态机、attention 恢复命令、fork pin 策略、扫描工具和帧差异阈值。
- 明确 10 秒源素材被 30 秒工程三个窗口重复引用、业务 shot ID 与 authored ID 的既有显式映射、`source.uri` 仅为不可执行元数据。

### 经事实核查驳回

- **“先实现 fork 才能通过实现前文档审查”**：倒置门禁。当前代码不存在新能力正是 D4.0 计划的开发对象；关闭判据应是计划精确到可实现与可验收，不是提前实现。
- **`UN_SUPPORTED_EDIT` typo**：源码 `project-write-actor.ts:185` 实际为 `UNSUPPORTED_EDIT`，全库检索无该 typo。
- **外部 op 与内部 mutation 必须同名**：跨边界映射是架构隔离，不是冲突；现已用映射表消除歧义。
- **客户端 envelope 必须带 `preimageSha256`**：会把 Hypit 所有的 Source 并发控制泄露给不可信客户端，违反路线 A；preimage 必须由 Studio 当前 revision/AST/磁盘计算。
- **把业务 `shot_id` 改成 Hypit `authored_id/item_id`**：违反 D3 已冻结的 stable business ID → authored ID → opaque item ID 分层；保留并明确映射。
- **要求 time Window 与 visual Clip 全局 ID 不同**：Hypit 已真实编译、写入、双 build 该 fixture；不同 semantic output 通过引用路径区分。D4.0 不为外审推测改写已验证 fixture。
- **0.3.1 与 `@hypit/markup@1` 是版本冲突**：前者是 distribution package version，后者是 Source frontend ABI request，不是同一版本域；文档已补充映射说明。
