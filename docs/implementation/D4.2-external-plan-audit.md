## 意见处理

| 外审意见 | 核查结论 | 修订 |
|---|---|---|
| derived 未强制 cleared/commercial | 有效 | AssetManifest v2 schema 与 Host 计划双层强制；新增 D42-MANIFEST-02 |
| generated + cleared 被认为冲突 | 不采纳 | 两字段正交：generated 表示 synthetic，cleared 表示许可；禁止组合将偏离 PRD。补充 UI synthetic 标记和 D42-SYNTHETIC-01 |
| lineage `not` 表达可能失效 | 原正反例已通过，但可读性不足 | 改为互斥 `oneOf`，再次用项目同版本 AJV strict 验证 |
| multipart envelope 缺契约锚点 | 有效，但不能采用 strict AJV 未注册 `x-*` | 用标准 `$comment` 固化 transport policy；Host parser/HTTP tests 负责强制，补 400/413/backpressure/磁盘满门限 |
| restricted + commercial=true 被认为非法 | 部分不采纳 | restricted 可能仍允许商业用途但有其他限制；允许入库、禁止 materialize。schema 强制 cleared→commercial=true；新增正反例测试 |

## 修订后本机验证

- 五份 D4.2 schema 使用项目同版本 Ajv 2020、`strict:true` 与 `ajv-formats` 全部编译通过。
- `derived+lineage+cleared` 通过。
- `derived` 缺 lineage、`derived+restricted`、非 derived 携带 lineage、`cleared+commercial=false` 均拒绝。
- `restricted+commercial=true` 可登记；计划明确 materialize 必须 422。
- `generated+cleared` MaterializedProposal 合法；计划和主架构强制 UI/证据显示 synthetic，不得冒充真实现场。

## 当前状态

上述结论针对 v0.2。开工前内部复核发现 D4.2.1 在 renderer 实现前承诺 materialized record，阶段自身无法用真实能力出门。v0.3 已把 D4.2.1 收窄为契约/本地导入/资产登记，把 binding、Job、composite 与 MaterializedProposal 整体移入 D4.2.2；总体 PRD 范围和目标架构不变。针对性复审完成前，原 `ALLOW_D4_2_1_IMPLEMENTATION=YES` 暂不作为开工许可。

## v0.3 阶段边界复审首轮

Claude Code CLI 确认三个新子阶段可分别用真实能力验收，且 D4.2.1 已无 renderer/materialization/adoption 隐式依赖；同时指出 2 项重大表述和 2 项必须修订：内部审计误称“仅调整归属”、@2 清单与旧 Hypit 的阶段间兼容窗口、已存在错误码的过期说明、@1→@2 迁移触发/补偿不精确。
