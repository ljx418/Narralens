# D4.2.1 路线 A：导入响应真实格式修订

日期：2026-10-14  
状态：负责人已批准，待合同测试与独立外审通过后进入 ImportService 实现

## 1. 发现的矛盾

既有计划要求 @1 工程遇到精确重复 identity 时不迁移并保持原 manifest bytes；旧版 `AssetImportResponse` 却把 `manifest_format` 固定为 @2。两项无法同时为真：若返回 @2 会虚报状态，若为满足响应而迁移则破坏“重复不写入”的事务与验收边界。

## 2. 批准的路线 A

`manifest_format` 改为 `narralens.asset-manifest@1 | narralens.asset-manifest@2`，始终返回事务结束时唯一活跃清单的真实格式。状态组合冻结如下：

| 起始清单与结果 | HTTP | created | migrated_from_v1 | manifest_format | manifest 写入 |
|---|---:|---:|---:|---|---|
| @1，精确重复 | 200 | false | false | @1 | 无 |
| @1，新增 identity 成功 | 201 | true | true | @2 | 原子迁移并追加 |
| @2，精确重复 | 200 | false | false | @2 | 无 |
| @2，新增 identity 成功 | 201 | true | false | @2 | 原子追加 |

同一 idempotency key 与 canonical request 的重放返回首次持久化的完全相同 status/body，不根据之后的 manifest 状态重算。

## 3. 合同约束

- `manifest_format=@1` 必须同时满足 `created=false`、`migrated_from_v1=false`。
- `created=true` 必须同时满足 `manifest_format=@2`。
- `migrated_from_v1=true` 必须同时满足 `created=true`、`manifest_format=@2`。
- schema、TypeScript、运行时 validator、审查快照与 SHA 固定测试必须同步修改。

## 4. 架构与体验影响

AssetRegistry 的“新 identity 才迁移”规则不变；ImportService 只需从实际提交结果构造响应。浏览器可以诚实显示当前工程仍为兼容格式 @1，不会因重复导入产生不可见写入。此修订不新增 PRD 功能、不改变 Source、Run、narration 或 revision，也不提前实现 D4.2.2。

## 5. 准入门槛

只有正反例合同测试、全量类型检查与 Claude Code CLI 只读审查均通过，且致命/重大问题为 0，才允许继续实现导入事务与 HTTP 路由。

## 6. 准入结果

2026-10-14 已完成：合同正反例与全量 `pnpm check` 通过（13 个测试文件、100 项测试）；Claude Code CLI 只读独立审查结论为 `PASS / ALLOW_IMPORT_SERVICE YES / CRITICAL 0 / MAJOR 0`。外审提出的唯一非阻塞观察是补齐 @2 重复与 @2 新增两种正例，现已纳入合同测试。路线 A 合同准入关闭，允许继续 ImportService 实现。
