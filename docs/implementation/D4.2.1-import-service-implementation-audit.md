# D4.2.1 ImportService、库存与路由实现审计

日期：2026-10-14

状态：`INTERNAL PASS / EXTERNAL BLOCKED (Claude Code 429) / UI_NOT_ALLOWED`

实现提交：`81c6c23f0d761fa417af99e16b10817bf5f12011`。

## 1. 本次实现范围

- `AssetImportService` 消费已冻结的 upload/media、AssetRegistry、import journal 与共享 `ProjectOperationQueue`。
- 内容文件从工程内随机 0700 staging 通过同文件系统硬链接原子安装到 `media/<sha>/source.mp4`，路径不使用 filename；安装前后复核 regular-file、symlink、containment、SHA、file fsync 与 directory fsync。
- 新增 `POST /api/projects/:id/assets/import` 和 `GET /api/projects/:id/assets`；响应关闭会取消尚未进入 commit 的媒体工具，进入 commit 后优先完成确定性事务。
- 启动时先恢复 import journal，再恢复既有 edit journal；`pnpm recover` 也使用同一共享队列处理两类 journal。
- 库存保持 manifest 顺序，不返回 `project_path`，每次请求重新流式哈希、ffprobe、再次哈希；最多两个条目并发，单项故障只降级本项。

## 2. 内部验证结论

本地全量 `pnpm check`：15 个测试文件、116/116；TypeScript 与 Vite production build 通过。`pnpm audit --prod --audit-level high`：`No known vulnerabilities found`。

真实测试已覆盖：

- 真实 MP4 从 @1 原子迁移到 @2，201、`created=true`、`migrated_from_v1=true`；内容 bytes 相等；Source、Run、narration、revision、Actor 次数不变。
- 同 key 重放即使当前 manifest 暂时不可读，仍返回首次持久化的完全相同 201/body；同 key 异请求为 409；新 key 精确重复为 200。
- 路线 A：@1 已存在 identity 返回真实 @1/200，manifest bytes 不变。
- 无效媒体在 journal/manifest 前 422；staging 清理。
- `manifest_published` 重启恢复为 committed；“manifest 已发布但 journal 仍为 bytes_installed”的崩溃点恢复精确 preimage，并只删除不再被引用且 SHA 匹配的本事务新 bytes。
- 库存对 available、restricted、missing、tampered 分项降级，响应中无工程路径或绝对路径；GET route 真实通过。

## 3. 内审修复

内审补齐了以下风险：幂等 committed 响应在 manifest planning 前命中；content/staging 的 lexical symlink 与 canonical containment 双检；inventory 在 ffprobe 前后双哈希；响应关闭向 ffprobe/ffmpeg 传播 AbortSignal；Host 自定义依赖拒绝共享队列不一致；手工恢复命令同时处理 import/edit journal。

## 4. 外审状态与停止原因

Claude Code CLI 在本轮可执行简单探针，但完整审查多次超时；最后一次明确返回：

```text
API Error: Request rejected (429)
已达到 Token Plan 用量上限：请升级 Token Plan 套餐或购买积分补充用量。
```

曾有一次只收到不完整代码片段的审查列出 6 个 major；逐项对照完整源码后，其前提分别与“只返回 committed cache”“#commit 位于共享 queue”“attention 仅在 after SHA + bytes rehash 后提交”“commit 开始后有意完成事务”“不确定 publish 精确补偿并记 compensated”“boolean 仅在 fsync 后返回”等实际代码冲突，因此不能将该片段审查当作有效 PASS，也不能把未经完整上下文的结论直接关闭。待额度恢复后必须针对完整实现重新审查。

依照既定门禁，本实现只作为已推送检查点，不声明 ImportService 子阶段外审通过，不进入 UI。恢复条件是 Claude Code CLI 完整只读复审得到 `critical=0 / major=0`；如出现真实问题，先修复并回归，再复审。
