## 5. 架构审查

- `ProjectOperationQueue` 是必须的共享并发实体，不是 UI/文档概念；Host 单例注入可防止 Actor 与 ImportService 各自维护互不知情的 tails。
- 上传/完整 decode 不占项目队列，只让短 commit 临界区串行；因此大文件不会无故阻塞 D3/D4.0 编辑数分钟。
- AssetManifest 是资产授权/索引事实，不是时间轴；ImportJournal 是恢复事实，不增加影片 revision，也不能重建影片。
- content-addressed bytes 可被多个 asset identity 复用；只有 manifest identity 保存来源/许可。删除补偿只删除本事务新建且当前无引用的 bytes。
- Hypit lease 区分 inventory identification 与 mutation target eligibility；restricted 条目不使整表不可读，也不能成为新 target。
- 新专项 Archify 图已 9/9 showcase、0 error、0 warning。官方 visual-check 首次因 Linux Chrome 不可用 skipped；显式传入 Windows Chrome 后因其不支持 WSL DevTools pipe 而返回 failed（`ECONNRESET`），按交付合同保留 failed、不归一为 skipped。补充 Windows Headless Chrome 1440×900 实图已人工检查，无可见重叠/截断/事实漂移；该单视口检查只支持有限感知复核，不能替代官方四视口自动证据，也不阻塞文档架构语义门禁。

## 6. 契约审查

- 七份 D4.2 schema 均需 strict AJV 编译；D4.2.1 仅四份进入 runtime，其余三份继续 docs-only。
- ImportMetadata 新 URI 只允许 http(s)；Manifest v2/Inventory 为 @1 无损迁移允许通用 URI。测试必须同时证明二者差异是有意兼容，不是 schema 漂移。
- Inventory 不含 project_path/filename/token；`eligible` 与 `blocking_reasons` 的跨字段一致性由 Host semantic validator 和正反例测试保证。
- ImportResponse 的 200/201、created/migrated 由第一次成功事务持久化；重放不重算当前状态。
- 新错误码必须同时更新 `ApiErrorCode`、api-error schema、HTTP normalization 和 UI 映射；不能只在字符串中出现。

## 7. 原子性与恢复审查

| 窗口 | 预期恢复 |
|---|---|
| 上传/解码中断 | 私有 staging 删除；无 journal/manifest/Source 写 |
| prepared 后、bytes 安装前 | recovery 验证 manifest 仍 before SHA，标 aborted；同 hash 可重试 |
| bytes 安装后、manifest 前 | 保留或删除无引用 content bytes；manifest 原 bytes；journal compensated/aborted |
| manifest replace 后、readback 前 | readback 成功则补 commit；失败按 preimage 原子补偿；不确定则 attention |
| manifest committed、idempotency response 前 | recovery 从 journal after SHA/entry/bytes 重建相同 status/body并 commit |
| import 与 Source edit 并发 | queue 决定顺序；edit 的 expected SHA 对相应版本有效；revision 只由 edit 增加 |
| Studio write 后 manifest 变化 | Studio 恢复 Source preimage/re-publish后 409；不能恢复则外层 Actor attention |

## 8. 测试与证据充分性

测试矩阵覆盖合同、multipart、Content-Length/chunked、backpressure、真实媒体、CFR/VFR、迁移、幂等、content reuse、项目队列、journal crash、磁盘/rename/fsync fault、Hypit lease、D4.0 真写回归、库存、NOWRITE、UI/a11y/security、大文件和 D1–D4.1 回归。

真实出门不能只靠 mock：至少一个真实 30fps MP4 成功导入/重启重读；一个 64 MiB 真实 MP4/降低 cap 的 backpressure probe；一个 @1→@2 fixture；一个运行中 Studio manifest 更新后 D4.0 typed replace/build；一个浏览器键盘导入路径。故障注入可用于不可稳定制造的 ENOSPC/fsync/crash，但必须与真实文件系统前后 SHA 绑定。

| M2 availability cache 新鲜度不足 | 有效风险 | 取消跨请求缓存；每次 GET 流式重验 SHA，并补同 size/mtime 篡改与 256 项并发/超时测试 |
| M3 409/423 code 不明确 | 有效文档缺口 | 固定 `IDEMPOTENCY_KEY_CONFLICT`、`MANIFEST_CHANGED`、`PROJECT_ATTENTION_REQUIRED` |

| M5 streaming/ffmpeg 尚不存在 | 实现缺口；缺工具测试描述有效 | 不提前实现；增加 `D421-MEDIA-03` 并冻结 cleanup/NOWRITE |

本轮不接受“额外增加 expectedSha256 参数”的建议：`manifestSha256` 已绑定 manifest bytes，entry 自带授权 bytes SHA；再增加同义参数会形成两个可能冲突的 expected 值。实现必须以 manifest SHA lease + entry SHA + 当前 bytes 重验关闭竞态。

## 10. 非阻断剩余风险

1. `busboy` 的最终版本、类型包和许可证需在实现前通过 lockfile/供应链检查；如 API 行为与计划不符，回到文档选择另一成熟 streaming parser，禁止临时自研。
2. Windows 对目录 fsync/rename 的行为与 Linux 不同；实现必须抽象原子文件操作并在本机 WSL/Windows 路径 fixture 上真实测试。无法证明 durability 时不得声称断电原子，只能收窄为进程崩溃原子并重新外审。
3. RSS 测量受 V8/OS cache 噪声影响；计划同时要求慢消费者 backpressure 事实，不能用单一不稳定阈值假绿。
4. Hypit write-after-manifest-change 补偿涉及二次 publish，是本阶段最高风险；先完成 fork 单元/集成/真实 D4.0 证据，再开放 Host import route。

风险均已有验证顺序和停止条件，目前不需要用户路线选择。
