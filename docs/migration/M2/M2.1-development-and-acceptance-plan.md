### 4.1 网关行为

| 输入 | 结果 | HTTP |
|---|---|---|
| known + `translated` | 返回 `TypedEdit`（= `EditOperation`），交 Host 既有 `ProjectWriteActor` 提交 | 走既有 `/api/projects/:id/edits` |
| known + `translated_host_service` | 交 Host 既有 `AssetImportService`；只写资产 manifest，**不**产生影片 revision | 走既有 `/api/projects/:id/assets/import` |
| known + blocked | 拒绝，`UNSUPPORTED_EDIT` + `reason` | 422 |
| known + read_only | 无副作用通过，不产生 TypedEdit | 200 且 `changed=false` |
| unknown（未登记 operation） | **默认拒绝** + 记录安全事件 `native_write_denied` | 422 |
| 带 `native_operation` 直传的请求体 | schema `additionalProperties:false` 拒绝 | 422 |

两种 translated 是不同下游：前者是影片 typed edit（会改 revision），后者是资产登记（不会）。
二者都不经过 adapter commit，仍由 Host 独占提交（AC-002）。registry 的 `policy` 字段
取值集合因此为 `{translated, translated_host_service, blocked, read_only}`；
`unknown` 计数必须为 0。

安全事件写入内存环形缓冲（可丢弃、非持久事实），仅暴露计数与最近 N 条 `entry_id/transport/reason`，
不记录 secret、绝对路径或内容正文。

## 5. 冻结类型与 schema

### 5.1 TypedEdit（discriminated union，禁止 `payload: any`）

**M2.1 不引入任何新的编辑语义。** `TypedEdit` 就是既有 `EditOperation` 的别名，
discriminant 沿用 `op`，目标沿用 `shot_id`，不做任何重命名或新形状：

```ts
// src/contracts/engine-types.ts
export type TypedEdit = EditOperation;   // { op: "set_visual_fit" | "replace_visual_asset", shot_id, ... }
```

理由（ADR D-07）：网关的 `translated` 输出必须能**原样**交给 `ProjectWriteActor.execute()`，
中间不得存在一层需要维护的字段映射；否则映射本身就是一条可能被绕过的代码路径，
且与 `AC-019`（legacy 合同不变）冲突。
未来新增 operation 时才扩展该 union，并同时提交独立 schema 与
`contracts/edit-operation.schema.json` 的兼容处理，不在 M2.1 发生。

### 5.1.1 EngineProjection 形状

`03_M2_M4_MODULE_DESIGN.md:9` 要求至少提供 engine identity、snapshot/revision/digest、
fps rational、frame count、稳定 clip/track/subtitle ID、整数帧范围、asset 引用、
可编辑能力、preview descriptor。本 ticket 冻结为：

```ts
// src/contracts/engine-types.ts（全部为纯类型，无 Node/React/adapter 依赖）
export type EngineKind = "hypit" | "openfilm";
export type Sha256 = string;                                   // /^[a-f0-9]{64}$/
export type Fps = { readonly num: number; readonly den: number };  // 既约, num>0, den>0
export interface HalfOpenFrameRange {
  readonly start_frame: number;          // 整数, >= 0
  readonly end_frame_exclusive: number;  // 整数, > start_frame
}
export type CapabilityState = "supported" | "blocked" | "read_only" | "unverified";
export interface CapabilityMap {
  readonly entries: Readonly<Record<string, {
    readonly state: CapabilityState;
    readonly reason: string;
  }>>;
  readonly fps: Fps;
  readonly fps_verified: boolean;
}
export interface EngineTrack {
  readonly track_id: string;
  readonly index: number;
  readonly clip_ids: readonly string[];
}
export interface EngineSubtitle {
  readonly subtitle_id: string;
  readonly source_ref: string;
  readonly content_sha256: Sha256;
}
export interface EngineAssetReference {
  readonly asset_id: string | null;
  readonly path: string;          // 相对路径、`/` 分隔、不含 fragment；与 manifest `assets[].path` 同名同义
  readonly content_sha256: Sha256;
}
export interface PreviewDescriptor {
  readonly kind: "hypit-studio" | "openfilm-studio";
  readonly url: string;             // 只读预览；不是 source 写入入口
}

export interface EngineProjection {
  engine: EngineKind;
  engine_upstream_sha: string;
  snapshot_id: string;            // M2.1 = 内容寻址的 source digest 前缀；M2.2 起为 SnapshotStore id
  project_revision: number;
  control_revision: number;
  source_digest: Sha256;
  fps: Fps;                        // rational；legacy frame_rate 由单向派生得到
  frame_count: number;
  clips: EngineClip[];             // 按 timeline 顺序
  tracks: EngineTrack[];           // 稳定 track id
  subtitles: EngineSubtitle[];
  asset_references: EngineAssetReference[];
  editable_capabilities: CapabilityMap;
  preview: PreviewDescriptor;
  problems: string[];              // 上游解析问题；非空即不可作为可写基线
}

export interface EngineClip {
```

#### 5.4.1 canonical 规则（逐条可实现，两个实现者必须得到同一串字节）

1. `canonicalJson(v)`：对象键按其 **UTF-8 字节序升序**排序后输出（非 ASCII 键同样按 UTF-8 字节序，
   与第 3 条 `files` 的排序使用同一个原语，不另设「ASCII 优先、非 ASCII 排后」规则）；
   字符串按 JSON 转义输出，不做 Unicode 规范化、不改变大小写；
   数字只允许整数（`Number.isSafeInteger`），禁止 `NaN`/`Infinity`/浮点；
   无 BOM、无任何空白字符。
2. 每个 `files[]` / `assets[]` 元素先各自 canonical 化。
   **排序属于 manifest 构造、发生在 canonical 之前**（`05_API_INTERFACE_SPEC.md:147`「进入 canonical 前」）：
   `files[]` 按第 3 条排序；`assets[]` 见第 4 条，不排序。`canonicalJson` 自身不重排数组。
3. `files` 按 `path` 的 **UTF-8 字节序**升序排序（`Buffer.compare(Buffer.from(a,'utf8'), …)`，
   不是 `localeCompare`）。
4. `assets` **保持语义顺序**（= 解析器首次发现的 BFS 顺序），**不排序**
   （遵循 `05_API_INTERFACE_SPEC.md:147`「数组保留语义顺序，只有 source files … 按字节排序」）。
   修订了本计划初稿把 assets 一并排序的写法，见 ADR D-09。
5. `source_digest = SHA256("narralens-source-v1\n" + canonicalJson(manifest))`，
   前缀是 UTF-8 的 `narralens-source-v1` 加一个 `0x0A`，不含 BOM。
6. manifest 不含 `digest`、`snapshot`、`access_time` 字段（`05:149` 的「without」是平凡满足）。

#### 5.4.2 引用闭包解析算法（确定性定义）

输入：`root`（绝对目录，已 realpath）、`roots`（Host 声明的相对路径数组）、`declaredAssets`
（可选的 `{path, asset_id}` 对，用于把 Narralens 资产登记映射进 `assets[].asset_id`）。

1. **规范化**：每个 root 与每个解析出的相对路径统一用 `/`；拒绝绝对路径（以 `/` 或 `\` 或盘符开头）、
   含 `..` 段、含 `\` 分隔符、空串。
2. **roots 排序与 role 先定**：roots 去重后按 §5.4.1 第 3 条的 UTF-8 字节序升序，
   该顺序只决定**遍历顺序**。**先对全部 roots 定 role，再走任何引用**：
   **Host 声明的第一个 root（即 `roots[0]`，排序前）→ `entry`**；其余 root 按 §5.4.3 表判定，
   但**声明为 root 的文件永不因被别的文件引用而变成 `scene`/`html`**（root 声明优先）。
   排序绝不可把其他 root 提升为 `entry`（ADR D-11）。
3. **visited 语义（钉死）**：`visited` 是「已入队或已出队」的规范化相对路径集合，
   在**入队时**加入。解析出的引用若其规范化路径已在 `visited` 中，直接丢弃，不再入队。
   这样每个文件最多出队一次，且任何环都不会导致重复入队或死循环，无需额外环检测。
4. **BFS**：FIFO 队列；出队一个文件，按 §5.4.1a 的抽取表取引用，按**匹配偏移升序**逐个处理，
   同名引用保留首次出现。
5. **fragment/query**：引用先取 `#` 之前的部分；`?` 出现在本地引用中直接拒绝
   （`SOURCE_REFERENCE_UNSUPPORTED`），不做猜测。纯 fragment 引用（`#foo`，base 为空）
   视为指向本文件，跳过。
   因此 `scenes/shot-01.html#t=0,10` 与 `scenes/shot-01.html` 解析为同一文件，
   fragment **不影响** role、路径、大小与 digest（这是 OpenFilm 的 `at`/`time` 语义，
   它属于 EngineProjection 的帧范围，不属于 source 字节闭包）。
6. **外部引用**：`http:`/`https:`/`data:`/`mailto:`/`blob:`/协议相对 `//` 一律不跟随、不发起网络请求，
   计入结果对象的 `external_reference_count`（**不进 manifest**，故不参与 digest）。
7. **路径安全与存在性（顺序钉死）**：对每个解析出的引用依次执行
   (a) `resolve(dirname(referrer), ref)`；
   (b) `realpath()`，失败（ENOENT 等）→ **立即抛出** `SOURCE_REFERENCE_UNRESOLVED`；
   (c) 断言 realpath 结果仍位于 `root` 的 realpath 之内，否则 `SOURCE_PATH_ESCAPE`
   （这一条同时覆盖 `..` 穿越与 symlink escape）；
   (d) 由 realpath 结果计算最终相对路径并入 `visited` 判定。
   顺序固定为 resolve → realpath → 包含性检查；不允许先对未 realpath 的逻辑路径做包含性判断再判存在。
   被引用文件**允许**相对其所在目录使用 `..`（scene 引用 `../assets/theme.css` 是正常的），
   `..` 在引用解析时消解，结果必须仍落在 root 内；只有**声明的 roots** 禁止含 `..`（ADR D-11）。
8. **`<base href>` 不在范围内**：本版本不解析 HTML `<base href>` 改写基准目录。
   含 `<base href>` 的文件，其后续引用按 `dirname(referrer)` 解析；若因此解析不到，
   结果是 `SOURCE_REFERENCE_UNRESOLVED`（fail closed），不会被静默忽略。
   这是本版本的显式限制，任何后续放宽都必须走 CR/ADR。
9. **fail closed（无部分结果）**：`SOURCE_REFERENCE_UNRESOLVED`、`SOURCE_PATH_ESCAPE`、
   `SOURCE_REFERENCE_UNSUPPORTED`、`SOURCE_FILE_ROLE_UNKNOWN` 一律**立即抛出**，
   不收集、不降级、不返回部分 manifest。digest 只有两种结果：**完整的成功**，或**一个错误**。
   调用方不得在收到错误时使用任何已计算的部分值。
10. 无法分类的扩展名 → `SOURCE_FILE_ROLE_UNKNOWN`（同第 9 条，立即抛出）。
11. 未引用缓存、候选目录、访问时间不进入闭包，因为它们不会被任何引用命中。

#### 5.4.1a 引用抽取表（按文件 role 钉死，两个实现者必须抽到同一批引用）

匹配一律在**原始 UTF-8 文本**上做，不做 HTML/JS 解析；引号支持 `"` 与 `'`；
匹配到的是引号内的原始字符串，之后按 §5.4.2 第 5–7 条处理。

| 文件 role | 抽取模式（正则语义） |
|---|---|
| `entry`、`scene`、`html` | `src="…"`, `src='…'`, `href="…"`, `href='…'`（`<iframe>`/`<audio>`/`<link>`/`<script>`/`<img>`/`<source>` 共用这些属性）；以及 `<style>` 块与 `style="…"` 属性值中的 `url( … )` |
| `css` | `@import "…"` / `@import '…'`；`url( … )`，**引号可有可无**：`url("a.png")`、`url('a.png')`、`url(a.png)` 等价，未加引号时取到 `)` 之前并去首尾空白（ADR D-11） |
| `js` | 仅静态形式：`import` … `from` `"…"`、`import` … `from` `'…'`、以及紧接的 `import("…")` / `import('…')`（`import` 与 `(` 之间不得有空白）。模板字符串、变量、含空白的动态 `import(…)` 一律**不抽取**；`import.meta.url` **不抽取** |
| `subtitle` | cue 行首的 `URI:` 之后的值（VTT `WEBVTT` header 块不抽取引用） |
| `settings` | **不抽取引用**（settings 是叶子；其引用的资产由 `declaredAssets` 显式提供） |
| `font` | **不抽取引用**（叶子） |

同一文件内出现多次的同一引用只计一次，保留首次匹配偏移。
上表未列出的属性（如 `<form action>`、`data-*`、`<meta content>`）**一律不抽取**，
以免两个实现者对「算不算引用」产生分歧。

#### 5.4.3 role 判定表（先到先得，BFS 顺序保证唯一）

| 条件（按判定顺序） | role / 归属 |
|---|---|
| 声明的 roots 中第一个 | `files[].role = "entry"` |
| 扩展名属于二进制媒体集合（`.wav .mp3 .m4a .aac .ogg .oga .opus .flac .aif .aiff .weba .mp4 .m4v .mov .webm .mkv .avi .ogv .png .jpg .jpeg .webp .gif .avif`） | 进 `assets[]` |
| 被 `entry` 角色文件直接引用，且扩展名为 `.html`/`.htm` | `files[].role = "scene"` |
| 扩展名 `.html`/`.htm` | `files[].role = "html"` |
| 扩展名 `.js`/`.mjs`/`.cjs` | `files[].role = "js"` |
| 扩展名 `.css` | `files[].role = "css"` |
| 扩展名 `.vtt`/`.srt` | `files[].role = "subtitle"` |

OpenFilm 另有一个 16 位 hex 的 `filmRev`（`revOf(text) = sha256(text).slice(0,16)`）。
两者不是同一标度，adapter 的规则固定为：

- 严格基线判定用 `ctx.baseRevision` + `ctx.expectedSourceDigest`（对 `film.html` 复算 SourceDigestV1 比较），
  **不使用** `revOf` 的 16 位值做冲突判定；
- `revOf` 只在把 OpenFilm 原生 `base` 参数喂给 `editProjectFilm` 时使用，
  且该参数由 adapter 用「本轮 `plan` 时刻读到的 `rev`」填充，是 adapter 内部 preimage
  （`02_ARCHITECTURE_L0_L1.md:109`：OpenFilm native revision 只作 adapter 内部 preimage）。
  它不能替代、也不能覆盖 Narralens 的严格 409。

**adapter 对上游返回的处理（不留解释空间）**：

- `problems.length > 0` → `film.html` 不可读（上游文档：
  「a film.html that does not read is the agent's to fix」）。
  adapter 抛 `ENGINE_UNAVAILABLE`，`problems` 原文只入脱敏日志，不进 HTTP 响应。
  绝不「尽力修复」或回退默认解析。
- `rebased === true` → **绝不**视为成功。adapter 丢弃 staged 结果，抛 `SOURCE_CHANGED`（409）。
  由于严格基线在**调用上游之前**已判定，正常路径不会让上游进入 rebased 分支；
  上游 `rebased:true` 只可能出现在基线校验之后仍发生并发修改的情形，此时按上条拒绝。
- adapter 只从 `doc` 映射投影，**不自己解析 HTML**，因此不存在第二套 HTML 解析语义。

`src/adapters/openfilm/openfilm-upstream.ts` 提供
`createPinnedOpenFilmUpstream(vendorRoot)`：先用 `.git` HEAD 校验完整 SHA 等于
`e70d9d93c7bebe3d634ff2caa6f7a738cdde59d3`，不等则拒绝（`ENGINE_UNAVAILABLE`）；
通过后用**动态** `import()` 加载 `packages/openfilm/studio/server/film.mjs`
并校验三个导出函数名。生产 `src/**` 无 `vendor/` 静态 import，也无 `spikes/` import。

真实探针 `tests/m2.1-probe/openfilm-upstream-probe.mjs`：在隔离 worktree
`/mnt/c/workspace/videoworkline/Narralens-openfilm-m1b` 中运行，**直接 import 生产模块**，
对隔离副本执行以下断言：

1. `inspect`：返回 3 个 clip（`shot-01/02/03`），`fps = {num:30,den:1}`，
   `frame_count = 900`，`problems = []`。
2. `capabilities`：返回的 `CapabilityMap` 对 §4 表中每条 operation 的状态都取自 registry，
   且 **OpenFilm adapter 在 M2.1 下没有任何 operation 为 `translated`**
   （`timeline.set_visual_fit`/`replace_visual_asset` 的 translated 路径只接 Hypit；
   `asset.import` 的 translated 路径是 Host 资产服务，不经 OpenFilm），
   也没有任何 operation 为 `unverified`（否则测试失败，触发 §4.0.1 的 EN-02.b）。
3. `plan` + `stage`：写入 Host 分配的隔离根；断言隔离副本**原工程** bytes SHA 不变（AC-005）。
4. 严格 base：先在隔离副本外部改一次 `film.html`，再用改前 base 调 `stage`：
   必须在**调用上游之前**返回 409 `SOURCE_CHANGED`，且隔离副本 bytes SHA 与拒绝前一致（AC-004）。
   判定用的是 Narralens 的 `expectedSourceDigest`（整数 revision 侧），不是 `revOf` 的 16 位值（§7 消歧）。
5. `SourceDigestV1` 对真实工程计算：闭包必须包含 `film.html`、3 个 scene、
   字幕 `.vtt`（作为声明 root）、`assets/narration.wav`；
   断言 `#t=0,10` fragment 未改变 digest（§5.4.2 第 5 条）。
6. `rebased` 复跑：直接调上游 `editProjectFilm` 传旧 base，确认仍返回 `rebased: true`；
   再确认该结果被 adapter 转成拒绝而非成功。
7. 投影健康：确认 adapter 对该工程**没有**产生任何 `translated` 的 OpenFilm 写路径
   （§8 fitness 第 11 条），即 OpenFilm 在 M2.1 不可写。

该探针结果作为独立 evidence kind（`real_upstream_probe`）保存；
它不替代 `pnpm check` 的确定性门禁，两者都必须通过。
探针只读隔离 worktree 的 `vendor/openfilm`，对其中的工程副本写入，且每次运行前重新复制副本、运行后清理。

## 11.1 外审返修后的口径变化（第二轮）

第一轮独立外审对 `fc3efb4` 判 `FAIL_REWORK_REQUIRED`（B-01、B-02、M-01..M-05）。返修后本计划
的口径变化如下，裁决见 `ADR-M2.1-001` D-13..D-18：

1. **已提交 digest 基线由 Host 持有**（D-13）。§5.4 原先只定义「如何计算 digest」，现在额外定义
   「拿什么去比」：`project_state.source_digest` 在项目首次登记时写入，此后只读。

2. **资产闭包纳入当前 bytes，并在与 manifest 不符时 fail closed**（D-14）。EN-04 的
   「阻止旧 base」现在有两条独立机制：基线比对返回 409；资产自身矛盾时直接拒绝计算摘要。
3. **能力表完整且 fail closed**（D-15）。§5.2 要求的 `CapabilityMap` 现在是每引擎每 operation

4. **固定 SHA 同时固定将执行的 bytes**（D-16）。§7 的可用性判据从「HEAD 正确」扩展为
   「HEAD 正确 + 无 tracked 修改 + 每个被加载文件摘要正确」。
5. **identity 是 realpath**（D-17）。§5.4.2 的顺序由「resolve → realpath → 包含性 → 逻辑路径 visited」
   改为「resolve → realpath → 包含性 → **canonical 路径** visited/入队」。
6. **证据可从 clone 复现**（D-18）。§11 的证据格式由被 git-ignore 的 `*.log` 改为
   `.txt`/`.cmd`/`.exit`，并新增完整性校验（存在、被跟踪、未被 ignore、摘要一致、
   捕获时干净、冻结提交后无代码变更）。
