## 1. 本阶段唯一目标

在不改写旧 Hypit 工程、不双写、不新建第二时间线的前提下，把已盘点的三镜真实 fixture 迁移为
OpenFilm 原生多 clip 可编辑副本，并证明关闭重开、改一镜、再导出和回退都可复现。M2.3 同时是
Wave 1 的组合验收点：M2.1/M2.2 不再分别做一次重复外审。

## 2. 必须先冻结的实体

- `MigrationService`：只编排，不解析任意 DSL，不直接 commit。
- `MigrationPlanV1`：old/new project、固定 engine/upstream SHA、source/snapshot digest、feature inventory、
  stable identity map、asset/subtitle/audio mappings、unsupported/loss、validation steps。
- `MigrationReportV1`：计划事实、每步状态、产物 SHA256、原工程 before/after SHA、重开/编辑/导出/
  rollback 结果；未知项为 blocking，不能激活。
- `MigrationActivation`：新副本只在 validate 全绿后原子绑定一个 engine；旧项目 binding/bytes 不变。
- `RollbackRecord`：停止新写、隔离在途 job、恢复旧项目入口、旧导出验证、新结果保留。

所有 schema/type/validator/fixture 必须同提交演进；绝对路径只在 Host 内部，不进入合同或日志。

## 3. 最窄真实垂直链

1. 对旧 Hypit 三镜 fixture 建立一致 snapshot，记录完整 source/manifest/资产 SHA。
2. 生成确定性的 migration plan；未知 feature、丢失字幕/声音/资产、未固定上游均 fail closed。
3. Host 创建全新 project id 和隔离 stage；调用固定 OpenFilm adapter 的 plan/stage/validate。
4. 验证 stage 是三个原生可编辑 clip，不接受 flattened MP4 或单 clip 替代。
5. 发布 immutable snapshot，再原子写新项目 active commit 与唯一 OpenFilm binding；revision 恰好初始化一次。
6. 关闭并重开新工程，真实预览/导出；修改中间一镜，revision 恰好 +1，再次导出。
7. 对新工程执行 rollback drill：关闭新写、隔离在途任务、重开旧 Hypit 工程并真实导出；旧工程
   bytes SHA 与步骤 1 完全一致，新工程/snapshot/report 保留用于审计。

## 4. 接口与路由边界

只允许新增 versioned migration 路由，并默认关闭到 capability/fixture 检查通过：

- `POST /api/migration/v1/projects/:id/migrate-copy`：创建持久 migration job；不接受服务器路径。
- `GET /api/migration/v1/migrations/:migrationId`：读取 report/status。
- `POST /api/migration/v1/migrations/:migrationId/rollback`：幂等回退；不删除新副本。

`materialize`、`impact`、`adopt`、`history restore` 继续 404；虚构 operation 继续 422。迁移 job 复用
M2.2 `PersistentJobStore`、lease、event/SSE、outbox；callback 只能登记 report/状态，不能绕 Coordinator 激活。

## 5. 事务、崩溃与恢复矩阵

逐边界注入崩溃：plan 已写、stage 部分写、validate 后、snapshot rename 后、active commit 前、binding
切换前、切换后 report 前、rollback 每一步。重启后只能得到以下之一：

- 旧项目仍 active，新副本未激活且可安全续跑/清理；
- 新副本完整 active，report 可重建且旧项目未改；
- 持久 attention，所有写入口 423，禁止猜测成功。

禁止混合 revision、双 binding、孤儿 running job、自动删除审计产物或用 git reset 回退。
