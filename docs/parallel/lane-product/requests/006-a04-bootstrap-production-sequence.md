## Decision

Add a MAIN-owned `ProjectCreationService` and a same-connection **initial commit** operation under the existing Coordinator/project queue. Reuse existing snapshot publication and `project_transaction`; do not call migration activation, insert fake migration rows, or make the PRODUCT repository a second commit owner. `cp_a0_project_origin` is the created-origin/root authority; a real committed initial transaction is what makes its snapshot committed.

The present source has no general creation implementation. A successful bootstrap Job alone is insufficient: resolver, projection, inventory and M5 must all consume a genuine created view before `project.create` is enabled. The CP SQL supplies reservation/origin, not those adapters.

## Smallest creation/recovery sequence

1. **Before any lookup/write**, MAIN dispatcher authenticates create scope, Origin/session and frozen `CreateProject`. Resolve the current intake head, canonical Brief and real Q/A closure, accepted content decision or legitimate legacy Decision, owner, exact version/digests, required answers and permission to initialize a local project. Separate hashes: Brief SHA belongs to `intake_confirmation.input_digest` and `origin.intake_digest`; content relay/run input uses CreativeInputClosure SHA. Never substitute one for the other.
2. **Reservation transaction R, same DB:** recall `(principal_id,project.create,key)` in `cp_a0_bootstrap_command`. 3. **Owned worker and one project queue:** acquire durable job lease/attempt, CAS command `reserved→staging`; filesystem staging name derived from this command/attempt and restricted to configured created-project root. ## Real blockers / decisions MAIN must close

1. **Trusted-create wire/SQL tension:** registry `project.create` is ordinary authenticated MCP (`contracts/agent-driven-a.registry.json:76`), and CP01 accepts content relay as content proof; frozen origin nevertheless requires `intake_confirmation_id` FK (`migration.sql:149`) to a real `channel=trusted_ui,action=project.create` row (`:49`). A content-only relay cannot manufacture that row. Require an actual existing matching trusted creation confirmation/registered trusted channel; if absent return the controlled trusted-UI path/APPROVAL_REQUIRED, or explicitly revise/freeze the authority contract. Do not silently promote MCP text to UI. This is independent of accepting topic/script content once.
2. **Created view/layout/rights evidence is not present in the existing APIs.** cp_origin gives root and initial snapshot, not roots/subtitles/frame_count/asset-license records for later snapshots. Minimal internal immutable bootstrap-plan/created source manifest can carry initial facts without new public wire; MAIN must define/freeze its exact shape and use it through resolver/projection/inventory, then define how adoption/history refresh the same genuine created authority. Existing `openfilm_projection_fact` requires migration_id and frame_count>0 (`src/host/adoption/adoption-store.ts:24,:60`); writing a dummy migration ID there is not a solution.
3. **Preproject assets have no general server lookup yet.** AssetRegistry is project/catalog scoped (`asset-registry.ts:62,:172`); MigratedLedger derives source provenance from migration. Nonempty Brief asset IDs cannot be resolved for a never-created project merely by calling its inventory. MAIN needs an explicit authorized local asset catalog/import provenance lookup (principal+assetID+rightsRef→server-owned path/hash/probe/license), then created inventory persistence. Missing proof blocks those assets; empty bootstrap is possible, real A film is not proven. Existing AssetManifestEntry is video/mp4 only (`src/contracts/types.ts:225`); narration must retain distinct real audio provenance, not a forged video entry.
4. **Script-before-create sequencing:** ArtifactPut requires a real project and SQL artifact_version FK requires project_state. With frozen API, simplest truthful path is Brief confirmation→initial authoring project→Script/Storyboard artifacts→new confirmed creative closure/RunPrepare. Do not invent a preproject script Ref or ghost migrated project to claim the entire script was durably stored before creation. If strict final script persistence before reservation is required, CP needs a precise preproject draft/artifact seam.
5. **Initial commit API and joined job result are missing, not a new-database problem.** Existing compose/atomic/transition primitives are sufficient to implement under MAIN, but current convenience commit/job methods cannot be nested and don't atomically include cp_origin/style/replay. Initial commit must not be a collection of independently committed calls.

## Cutover dependency / acceptance boundary

Enable the frozen production `project.create` handler only after: trusted-create policy resolved → same-DB reservation+initial commit/recovery → genuine CreatedProjectView/root containment → created layout + rights inventory → Host/M5/source/adopt/history consumers accept created origin → job/context projections/native unconfirmed → two-topic/replay/conflict + crash/reopen proof. Keep handler CAPABILITY_UNAVAILABLE while missing; don't use a module test or manual layout map to turn it green. Existing migrated/legacy flows stay their own genuine origin and must regress unchanged.

## MAIN factual correction: nullable draft bootstrap is an admitted A04 path

This addendum supersedes any implication in “Real blockers” items3/4 or the cutover list that a script, narration asset, or nonempty asset catalog must exist before an empty draft project can be bootstrapped. MAIN verified CP01 §85 and the production runtime DTO: `Brief.narration_asset_id` and `ContentBrief.script_ref` both permit `null`.

The explicitly valid sequence is **idea → nullable draft Brief → genuine empty native authoring project → project-scoped Script/Storyboard artifacts → revised Brief and confirmed creative closure/WorkflowRun**. Persisting the script after creating the real project is the contract path, not a workaround or a missing preproject-artifact capability. No fabricated preproject ScriptRef, voice asset, migration record, placed content or completed-film claim is needed. An unselected narration asset must remain null; an initial empty project does not require voice production.

Asset authorization remains an actual-use boundary: before selecting, copying, assembling, generating from, or otherwise using a concrete asset, MAIN must resolve its actual registered identity/bytes/provenance and applicable rights through the genuine catalog/rights path. Missing proof blocks that asset use; it does **not** block a draft bootstrap which selects no assets. Created layout/resolver support for a genuine zero-frame authoring project and durable initial commit/recovery remain implementation dependencies, not a requirement to invent media or duration.

The nullable draft allowance does not relax creation authority: `cp_a0_project_origin.intake_confirmation_id` must still reference genuine matching `trusted_ui` creation confirmation. A content-only relay or null script/narration value cannot manufacture that evidence. MAIN should gate empty-draft bootstrap on its actual creation permission/confirmation and source/commit/readability invariants, then apply catalog/rights and closed-input requirements when the later workflow actually uses assets.
