# H-R1 callback delivery failure correction

BRIDGE independent read-only review found a genuine check1 defect: publish swallowed callback exceptions, so failed initial pending delivery could be followed by same-round read/hash and hydrated delivery after the receiver recovered. Earlier UI types/build0 did not cover it. The old8-file source archive, source manifest, internal contract manifest, full patch and helper are retained under check1; original check1 build archive/logs are unchanged.

Only actual helper behavior changes: publish returns boolean; no/undefined receiver or a throwing callback is false. observe aborts/increments the current round immediately if pending delivery fails, before any read/hash. Final delivery failure also ends its current round. No same-round implicit retry; a later independently initiated normal round can succeed. Exceptions remain contained and do not change original editor state/reducers. Film observation v1, hydration value shape/canonical contract, API/Preview/Player/clock/undo remain unchanged.

It appends only a test export for the private class; React and Host are narrow VM stubs, root is only an isConnected probe object, reads are injected functions and crypto is real Node WebCrypto. This is **unit behavior evidence, not React render/DOM/browser/native HTTP or Host proof**. No package is installed and no network/producer is started.
