## Event

Exactly project_id:string (same actual native ProjectView project ID as film observation, mapped by MAIN's private session), editor_view_id:string (same useFilm view UUID), document_epoch:nonnegative integer (same current useFilm epoch), hydration_epoch:positive monotonically increasing integer per view, parts:{settings,subtitle_style,captions,markers}. Each part exactly `{state,origin,effective_sha256}` with state pending/hydrated/absent_default/dirty/failed/unsupported; origin project/explicit_default/browser_preference; hash64lowerhex or null. Only hydrated/absent_default may carry a nonnull hash. Old view/session/generation/epoch or lower hydration epoch cannot advance MAIN's current profile. Pending/dirty/failed/unsupported invalidate readiness. Callback exceptions are caught; no credentials/source bytes/paths or approval authority are published.

`lib/native-hydration.ts` defines these types and the exact effective-value types alongside `lib/host.ts`. The observer keeps only read outcomes/versions and ephemeral hash projections; the original settings/style/captions/markers state is still the sole consumed business state. It creates no document/timeline/clock/store or file writes.

## Exact effective preimage

SHA256(UTF8(canonicalJson({format:'narralens.native-hydration-effective@1',part,value}))). Object keys sort using JS Object.keys(...).sort(), no whitespace; array order retained, strings/numbers unchanged, no trim/translation/Unicode normalization. Undefined object properties omitted consistently with native optional fields; arrays with non-JSON members/nonfinite numbers/nonplain objects fail closed. JSON-domain source vectors in effective-goldens.json use only defined JSON values. `generate-goldens.py` computes literal inputs/hashes, not a runtime test of the actual TS helper or native parser; that comparison remains NOT_RUN.

- **settings value** = `{settings:ProjectSettings,resolved_fps:number,fps_source:'project'|'footage_or_default',track_names:{doc_index:number,name:string}[],track_heights:{lane:string,doc_index:number|null,index:number,height:number}[]}`. settings is the actual ProjectView state object from the original parsed GET/PATCH. track_names is the actual `trackNames` override Map passed to native Timeline, entries sorted numeric doc_index; no invented names for absent overrides. track_heights is the actual `tools.tracks` row order passed to Timeline, height = actual row.height or the same pin's ownTrackHeight(row), including overlap rows. resolved_fps is actual projectFps consumed by native timecode/frameRate; fps_source is project only when settings.fps exists, otherwise the native footage/default branch. No inference of precise asset FPS source beyond that. Host must reproduce the same original timeline/track-name/height algorithms, not substitute its own frame_count or default names.
- **subtitle_style value** = the full actual `subs.style` object, typed upstream SubtitleStyle; all nested font/pos/stroke/shadow/box/karaoke/language/bilingual/on fields present exactly as current native state, optional native keys follow canonical omission. No styling rewrite. Project style success origin=project. Missing project style can be absent_default/origin explicit_default only if the native hook actually started with no browser remembered style and fresh same-epoch GET again returns null and actual style equals pinned SUBTITLE_DEFAULT. Browser remembered style remains origin browser_preference and unsupported/null, even if it happens to equal default. Local style edits remain dirty/null. Host expected source/default profile must match and reject malformed present styles despite upstream swallowing read errors.
- **captions value** = `{cues:actual captions.cues,sourceLanguage:actual captions.sourceLanguage,languages:actual captions.languages,untranscribed:actual captions.untranscribed}`. cues retain native order and original upstream FilmSubtitleCue fields (startMs,durMs,text plus optional speaker/words/alt/clip/src/line/part), no truncation/filtering/translation. This same raw state feeds native subtitle inspection/derived overlay. untranscribed nonempty does not mean ASR succeeded or failed to load the editor. Host derives expected cues with pinned film/transcript/translation/trim/duration rules on its actual closure. No ASR/translate/write producer is invoked by observer.
- **markers value** = `{placed:{marker:actual parsed Marker,ms:actual placed film time,clip_id:actual placed clip.clipId|null}[]}` from the existing `placed` memo that feeds native markerLane/overlay; preserve existing time order. Marker contains native id/t and optional clip/name/color. Parsed but not placed clip markers are deliberately absent from effective display value; raw source integrity and expected placement are MAIN facts. The revalidation basis still compares the entire actual parsed marker list, so stale unseen rows are not silently accepted.

settings/captions/markers revalidation origin is project and state hydrated, including a legitimate empty parsed result. These do **not** assert the physical sidecar existed: upstream settings/markers endpoints can normalize absence/parse/read errors into empty objects/arrays. MAIN must strictly verify present source files and exact workspace and match expected parsed/effective values before final NativeAck. No metadata callback alone certifies raw I/O success when the original API hides it.

## Original GET outcome / same-epoch revalidation

Original native GETs remain in their old effects and continue to set original state as before; each now records a request-start ticket and native success/failure/dirty metadata. A native response itself never creates hydration proof. A native outcome recorded from an older document epoch first remains unsupported/null. Native GET failure stays failed and is never upgraded by observer-only revalidation. Local dirty is conservatively sticky for that view; no verification GET clears it. A new editor view/original clean load can establish a fresh profile; no observer writes to make state appear clean.

Because native initial settings/style/captions/marker GETs race the initial film GET, a strict token check on only those original requests would make ordinary first load permanently unknown. MAIN explicitly authorized one current-epoch **read-only revalidation of the same existing GET** after real ProjectView layout commit. It never sets/reseeds native state, reruns style initialization, writes subtitle preferences or starts a media producer. It compares current actual native basis (settings/style/full captions/parsed markers) to the fresh parsed result, plus expected source origin. Only equality can hash the actual consumed effective projection. An older original request may set native state per unchanged legacy behavior, but cannot mint proof on its own; it needs a separate genuinely current read matching that state.

Revalidation captures immutable view identity + current valid document epoch + aggregate round/request token + part version. On GET return, after async SHA256, and just before DOM callback those must still match; original request changes, dirty, new checks, source events, new document, unmount, DOM root replacement or disconnected root abandon the old result. Callback after all part work still requires the same real root connected/current. No GET-response interception/onSelection/queue-settled is treated as DOM proof. Pending/invalidating events may be sent immediately with null hashes; only the post-layout path can publish hydrated hashes. Metadata render revisions are not another business-state store.

Normal first-open positive is expected only when original native reads succeed and matching real current-epoch revalidation succeeds. Fallback/browser preference/dirty/mismatch remain unsupported or dirty without fake success. Source/profile matching and selection/session/currentness remain MAIN's server gate. Hydration event never means video decoded, audio audible, cue burned, ASR complete, delivery ready or an approval consumed.
