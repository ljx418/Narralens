### What the three stages actually do

- `prepareEncoded(RenderRequest)`: reads the committed snapshot, runs the real preflight,
  copies the closure, asks the fence again, renders with the real renderer, verifies the
  copy, writes the bytes into an immutable private object under a UUID with file and
  directory fsyncs, publishes it with a rename, and only then returns the encoded fact.
  The fact carries no QC verdict and no readiness. A closure that does not state its
  frame count is refused (`SNAPSHOT_LENGTH_UNKNOWN`) rather than given a made-up zero.
- `inspectEncoded({request, encoded})`: reopens the encoded object, re-derives the
  closure and rights digests and refuses a closure that is no longer the one the film
  was rendered from (`CLOSURE_CHANGED`, `RIGHTS_CHANGED`), re-verifies every object file
  against the fact that named it, runs the real quality control and writes its **own**
  immutable evidence object. The encoded object is never altered by the inspection.
- `publishValidated({request, encoded, qc})`: reopens and re-verifies both objects,
  refuses a blocked inspection (`QC_BLOCKED`) and a warning without a recorded
  disposition (`QC_DISPOSITION_MISSING`), refuses a receipt whose digest does not
  describe it (`RECEIPT_DIGEST_CHANGED`) and an inspection that is not about this
  encoded fact (`QC_PARENT_MISMATCH`), and publishes through `PublishedPackageStore`,
  which stays the only public publisher. Nothing is rendered again.
- The resolver `openPhaseObject({object_id, relative_path, sha256, bytes, signal?})`
  opens the file with `O_NOFOLLOW`, checks the size and the digest **on the descriptor
  that serves the bytes**, and bounds every read to 1 MiB. It never accepts a path or a
  URL.
- A successful object is never removed: not by `close`, not by a later failure, not by a
  retry. Only an untransferred staging directory is ever deleted.
- The phases never call `claimAttempt`, `releaseAttempt` or `commitReady`: the executor
  owns the lease and the durable facts. The legacy facade is not used as a
  chapter-stage executor.
