## 3. 发现与闭环

### 已关闭

1. **原型通过与实现通过混淆**：拆为 Gate P、DOC、D1、V1。
2. **代码实体不具体**：补充 `NarralensApp`、`SelectionCoordinator`、`ProjectWriteActor`、Adapters、store、目录和依赖关系。
3. **验收“三无”风险**：每个 Gate 和 E2E 场景均补齐用户操作、步骤、证据和出门门限。
4. **第二时间轴风险**：架构、追踪矩阵和测试约束共同禁止 UI/DB 保存最终影片结构。
5. **虚假验收风险**：明确静态页面/mock 只能证明 UI/契约；真实能力要求 MP4、ffprobe、帧样本、哈希、重开和日志。
6. **计划跳阶段风险**：D1 失败直接停止业务 UI；每阶段必须有 evidence manifest 才能前进。

## 4. 技术路线

### A｜薄集成固定 Hypit + OpenMontage（当前基线，推荐）

- 优点：复用真实播放器、时间模型、渲染链与 agent 制作能力；最符合 PRD 的统一工作台。
- 缺点：受上游扩展点、许可和版本稳定性约束。
- 进入条件：Gate D1 全绿。

### B｜固定 Hypit fork，OpenMontage 仅离线产物交换（D1 部分失败时备选）

- 优点：降低 Runner 与 Host 的实时集成复杂度，保留 Hypit 真实工程链。
- 缺点：提案链反馈较慢，统一工作台体验退化；仍不能手工复制 JSON 作为最终方案。
- 触发条件：OpenMontage 无稳定在线入口，但可稳定生成结构化产物。

### C｜自建编辑/渲染底座（No-Go，除非重新立项）

- 优点：完全控制。
- 缺点：显著扩大范围，重复开发 NLE/渲染器，当前文档、周期和许可评估均不足。
- 结论：不属于 V1；若选择需重做 PRD、架构、里程碑和预算审批。
