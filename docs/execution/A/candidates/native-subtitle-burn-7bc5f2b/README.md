# Direct Node native subtitle burn helper

The only runtime implementation is native-subtitle-burn-source.mjs. It imports node:crypto directly and has no native-draft-plan/TS/js-loader dependency. Its adjacent .d.mts declares the runtime and TS compatibility entry re-exports values/types only; there is no duplicated helper implementation. MAIN can import the actual .mjs in its Node worker before upstream loading under its own reviewed worker/graph pin. This lane does not modify that worker or pin.

Valid original input retains the exact original template literal bytes (independently compared against full baseline Git blob), including native ready/frame/time/settle, __filmSounds and __filmCuts forwarding, stage dimensions, caption JSON, and forced subtitle-on behavior. Module bytes are copied before their fixed SHA check; output contains that copied exact module and the same wrapper page. Native normalized style semantic validation still belongs to the pinned native style seam; this helper checks it is plain JSON data, not a second style parser or renderer.

Boundary validation rejects missing/extra top fields, wrong module SHA, non-Uint8Array bytes, malformed stage, missing/non-object style, sparse/invalid/out-of-film cues, nonfinite JSON, functions, accessors/toJSON, cycles, prototype-sensitive keys and symbols. Fixed ordinary Error messages contain no input values or paths; unknown exceptions are replaced without reading their message/getters. No file/process/network/Job effects occur in the runtime helper.
