## Interface and transaction

CreatedTaskStore(revisions, ports, now) captures the same db via RevisionStore.compose; uses existing OperationIdempotencyStore.recall/record raw methods, revisions.createJobRow/appendJobEvent(withinTransaction=true)/enqueueOutbox and one RevisionStore.atomic BEGIN IMMEDIATE per mutation. No DatabaseSync construction, nested PersistentJobStore.create/ProductRepository.transaction, new job/commit state machine or changed CP DDL/DTO.

reserve(TaskPrepare,principalId,{job_kind,max_attempts}) returns {accepted:original queued JobReceipt,stage_token,replayed}. Validate/freeze request before async/no actual async method. Digest domain canonical{principal_id,request without meta}; correlation-only changes replay the original accepted response. MAIN explicitly chooses existing job kind and positive safe max_attempts; no default or hardcoded budget. Sync assertAllowed(db,context) executes inside BEGIN before ledger lookup and again after mutations with fresh clock. Same operation ledger kind agent.v1:task.prepare/project/key; same key+same digest returns original queued receipt, not current job state; different digest409. Different key for occupied project/run/plan/step/execution attempt conflicts even with same payload. New reserve inserts job, immutable input row, original ledger, queued job_event, task outbox and sync bindStep(db,context) in this same transaction. Both hooks reject thenables and throw to roll back. Hook must not swallow its own SQL errors or start its own transaction. Store validates job/input relation at final boundary. bindStep is MAIN's missing synchronous original step/checkpoint linkage; no fabricated production Run proof in candidate.

recordPrepared(job_id,lease{owner,attempt},fact,proof) validates immutable fact shape and uses BEGIN/fresh clock. Require actual job state running, project/payload matches input, exact lease_owner and job.attempt (the existing lease attempt), unexpired lease; cancel/terminal/late/expired refuses without mutation. MAIN assertPrepared(db,context) verifies Host-issued stage proof, real files/roots/source/rights and current scope both before and after inserting fact, with a fresh final lease/time recheck. Store cannot infer filesystem/rights truth from JSON. Same existing fact is returned only under a still-live current lease; different fact conflicts. Never mark job succeeded or advance cp step; existing state store/Coordinator owns that. stage_token is Host-random opaque token persisted on reserve and reused, not an absolute path/URL or client-selected field. Prepared is a fact, not commit, snapshot publication or authority.

## SQL namespace v1

created_task_input: PK job_id FK existing job; immutable principal/project/execution identity, original validated request_json and digest, unique stage_token, original accepted_json, created_at. UNIQUE(project_id,run_id,plan_version,step_id,execution_attempt) prevents double jobs. No execution state column. created_task_prepared: PK/FK job_id; stage_token, immutable fact_json/digest, recording lease owner/attempt and prepared_at. Trigger UPDATE/DELETE abort for both. Own namespace uses matchesFrozenSchemaNamespace fixed-definition compare before reuse and on runtime schema_version changes. Fresh namespace created transactionally only when absent; partial/unknown definitions rejected, not repaired. No writes to frozen cp_a0_* schema.

Fact: {format:'narralens.created-task-prepared@1',stage_token,source_digest,plan_digest:null|hash,rights_digest,files:[{relative_path,bytes,sha256}],roots:[safe relative path]}. Require exact keys, nonempty unique files/roots, safe POSIX relative no dot segments/backslash/control/absolute/URL, roots present in files, positive safe bytes, full SHA256; deterministic fact_digest from canonical JSON. Input fact binds original project/base/source/inputrefs/render_spec/execution through immutable original TaskPrepare. No mutable stage status or second readiness.
