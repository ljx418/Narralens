## ND-R1 — MAJOR: created-root identity is recorded but not enforced when opening

`native-draft-io.ts` `#initialize` successfully mkdirs the root and saves `#createdStat` from lstat. It then awaits open and stat, assigns `#target` / root `#outputDirs`, and checks privacy/uid but **never compares the opened directory inode with the previously recorded created inode**. `verify` compares only against the subsequently adopted target stat. `#createdStat` is otherwise used only during failure cleanup.

Concrete source-derived sequence: mkdir creates A; the awaited lstat records inodeA; before the awaited open completes, renameA aside and put another real0700 directoryB at the same target pathname. The NOFOLLOW open correctly refuses symlinks, but accepts realB. #target recordsB, and later verify sees currentB==recordedB, so it passes. IfB is empty and private, files can be written and finish can succeed. The assembler thereby writes a replacement directory it did not create. This is distinct from the already tested ancestor→snapshot symlink swap: fd-relative writes correctly prevent redirection after a directory is anchored, but the initial leaf identity is not bound to the creation record here.

At minimum compare directory type +dev/ino of the opened stat to#createdStat before admitting the target/outputDirs. Failure must close the new fd and leave replacedB untouched; cleanup must continue using recorded inode guards. A file-only negative can inject precisely between completed root lstat and root open, replace with a real private directory, and assert rejection/no bytes inB. No test was run by this reviewer, so this remains source-derived rather than experimentally reproduced. The still earlier mkdir→first-lstat interval is not certified by this proposed minimum fix; avoid claiming an atomic mkdir/open identity acquisition without a concrete ownership protocol.
