## MR-R1 — running identity guard misses an aliased runtime-root ancestor

`managed-editor.mjs` `identityGuard` records lstat(dev/ino/size/mtimeNs/ctimeNs) of the final editor directory, its pinned leaves and assets directory. Unlike `canonicalDirectory`, the returned guard does not recheck ancestor symlinks/canonical identity. `isolated-studio.isAlive` directly trusts this guard alongside process identity.

Source-derived deterministic scenario: after successful prepare/start, rename the complete runtime directory to a sibling path, then symlink its former pathname back to the moved directory. The editor directory and all nested leaves remain the same objects with unchanged recorded fingerprints; lstat of each complete editor/leaf pathname resolves the intermediate symlink and sees the same final object. Therefore `managed.isCurrent()` remains true although the running editor's ancestor pathname is now an alias. The runtime-root inode itself was not captured. No file bytes need change. This has not been executed by this reviewer because no test resource was granted.

This is a concrete continuous no-alias/identity-lease blind spot, not evidence of arbitrary browser-selected paths or a demonstrated unauthorized write. It requires filesystem mutation by an actor able to move the runtime parent. Startup canonicalDirectory/child revalidation correctly reject preexisting aliases; the gap is specifically post-publication/post-launch ancestor replacement. Add runtime-parent canonical/identity revalidation to the guard (or retain equivalent anchored identity), while preserving the existing file fingerprints. A targeted file-only negative can distinguish ancestor rename+alias from intact immutable publication.
