## CNE-R1 — MAJOR: ordinary reopening exhausts native entry capacity for eight hours

`controlled-studio-access.ts` lines 31–34 only collect time-expired records. Lines 47 and 102 reject when proofs reach 64. Each successful exchange at lines 103–104 allocates a new proof/read-token pair with an eight-hour lifetime. No release, reuse, or inactive-grant collection exists. `recheck` rejects invalid owners/copies but does not remove their records.

Concrete reproduction: with a valid owned committed project and an active UI session, repeat native-open and ticket exchange 64 times, then request native-open again. The 65th open returns 503 CAPABILITY_UNAVAILABLE. Closing tabs does not release entries. Revoking the previous owner UI session and signing in again also leaves those old proof records occupying the shared Gateway capacity until their original expiry. Expiring the five-minute ticket does not help: redeemed tickets were removed and the eight-hour proofs remain.

Repair should define session reuse or explicit safe retirement and collect stale grants, preserving concurrent tab proofs and the stable transport cookie. A negative control should show renewed UI authority cannot revive revoked sessions, while a sustained ordinary reopen sequence can still obtain a usable current entry. This is a deterministic source-derived reproduction; it has not been executed by this reviewer.

## Boundaries actually inspected

- `CreationApplication` obtains the caller from authenticated trusted UI; `prepare` checks real owner/commit. After Supervisor.ensure, it checks current principal and exact prepared object before issuing a grant. The resulting closure rechecks both on later use. Native ID is taken from the real Supervisor descriptor, not the request body. Host issueNativeEntry refuses closing/unconfigured Host.
- `isPrepared` checks the issued object identity, active tuple, held directory/root inode identities, canonical paths, and closing state through #check. It is a lightweight delegate check, not fresh hashing of every large asset per request; Studio edits remain confined to the disposable copy.
- Native API routes enforce exact native ID, read-only methods and closed read allowlist. `/api/projects` is filtered to that ID. Native writes fail closed, and native panel operations currently allow only the real matching workbench projection. Read tokens cannot mint Host/UI authority or approval.
- Film access requires the session read token and exact upstream-key-derived current-native-ID HMAC path prefix. The pinned vendor film server independently decodes/checks safe paths. Unscoped film paths are denied. JSON and event film URLs are rewritten through the scoped prefix; error responses use fixed text rather than upstream exception/path strings.
- API/film awaited upstream reads and awaited workbench reads recheck delegate liveness before returning bytes. WebSocket accepts only editor Origin plus the read capability, routes both global and project listeners to the single delegated project, checks on frames and heartbeat, and closes on Gateway shutdown. Browser cookie alone cannot authenticate private editor APIs; proof is stored per origin in sessionStorage. Different tabs keep separate proofs under the shared stable Gateway transport cookie.
- Browser fetch proof injection is limited to same-origin private routes. Media URL injection is limited to matching native project media/poster endpoints. Ticket is consumed once from a fragment and removed from the address before exchange. Server-side expiry, revocation and prepared-copy liveness remain authoritative.

These source observations do not establish exhaustive race freedom. MAIN reports HTTP/headless success; this review did not rerun or independently certify those results. NativeAck remains unknown; raw native writes remain denied. No legal new-DB-revision race, general writable editor workflow, producer execution, or complete A workflow is certified here.
