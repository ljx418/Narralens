# CNE-R1 repair — read-only source recheck

Status: original CNE-R1 is **covered by current source repair, NEEDS_TEST**. This supersedes the original report's statement that the defect remains in current source; the original finding and input hashes remain historical. Actual repaired byte hashes are in `r1-fix-input-hashes.json`. No test/compiler/browser/service was run by this reviewer, and no MAIN files were modified.

`#sameScope` compares owner_session_ref, public project, native ID, Host generation, revision, snapshot and source digest. After body completion, `exchange` collects expired/inactive grants, validates the ticket's current grant, and synchronously reuses only the exact matching current session. The existing proof/read token/cookie and fixed expiry remain unchanged. A different scope allocates a separate session and cannot obtain another scope's proof through this reuse path. The production closure now also checks the captured generation against the live runtime generation.

`#collect` removes inactive/expired tickets and both indexes of inactive/expired sessions. Retired entries contain only token hash and deadline; no grant/callback/authority is retained. Five-minute tombstones are capped at 256 entries. They only preserve a temporary stale response, and never authorize reads. Expiry is not extended by reopening. Unknown/evicted tombstones fail as unauthorized rather than reviving a session. A retained session reference in an in-flight request or existing WS is checked against the live proof-map object, so collection prevents its later reuse. The post-body exchange path has no await between collection/current validation/reuse and response construction; I found no new interleaving window introduced by this repair.

The new HTTP harness tests expressly remain component transport evidence: 80 same-scope exchanges preserve the proof/read token/cookie and the original tab remains usable; 64 distinct owner records become inactive and are reclaimed before a new owner is accepted, while an old proof returns stale. The existing actual native integration still checks differing prepared-copy/native IDs are rejected and that normal same-scope reopening preserves the original proof. These test sources were inspected, not executed here.

No additional concrete authorization regression was identified in this limited repair review. This is not frozen acceptance or a full A05/A/security PASS. The live-session limit of 64 distinct current scopes and 64 unconsumed five-minute tickets remains an explicit bounded capacity; the former ordinary same-scope reopen exhaustion no longer follows from the repaired code.
