# Committed media package lineage repair (MAIN)

Internal package supplement phase_lineage.json binds original encoded receipt digest, QC receipt digest and the actually dispositioned QC items digest plus project/snapshot/source/config. It is written/fsynced in attempt staging and its Ref appears in the original DeliveryManifest.supplement_refs. No new wire field, JobKind, approval authority, ready state or package-store state machine is introduced. Existing generic immutable package store and original download/manifest contracts remain authoritative.

PublishedPackageStore deliberately preserves a first winner for the same delivery key. Before returning a PublishedPhaseReceipt, CommittedRenderPhases must compare the winner's complete verified file identities/names/digests/sizes with current encoded/QC/lineage facts and compare QC and supplement refs. A different MP4, identical MP4 but another encoded/QC parent, changed disposition, or legacy package without lineage fails closed with private PACKAGE_LINEAGE_CONFLICT. It leaves the existing winner untouched. It must not attach current parent digests to an old winner merely because snapshot/config/key match. Same exact parent chain may be observed under a later publication lease; original package receipt/attempt/time remain unchanged, while outer phase records current publication execution/lease truthfully. Legacy SnapshotRenderService and existing legacy execution entry remain unchanged and can read their own packages; this additive phase path does not guess lineage for them.

Pure module evidence includes real immutable PublishedPackageStore, fake encoder/QC, independent complete expected file facts, and old/wrong-parent negatives. Actual renderer, Host executor, DB final lease fence, complete A workflow/export/human acceptance are not thereby proven. Independent review pending.
