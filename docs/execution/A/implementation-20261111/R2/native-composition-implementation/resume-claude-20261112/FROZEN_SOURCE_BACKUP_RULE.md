# N1/N2 后续冻结输入保全

本规则仅加强已授权实现的证据保全，不增加产品功能或修改 runner；不解锁任何业务运行。MAIN 后续放行每一份候选前，应逐字保存该候选白名单源码/测试字节（含相关受保护回归文件），并把实际路径、完整 SHA256、只读备份路径写入该 grant 的输入映射。

备份放 canonical 控制目录的 source-captures 内，以完整 SHA256 命名为 .txt；只是不可执行的源码证据，不是替代项目或第二实现树。只读取本 ticket 明确白名单和受保护回归文件，不收集配置、环境、凭据、媒体或用户素材。不进入 implementation worktree 的 src/tests/tools/config，不改变其编译和运行输入。

记录必须基于同一次读取的真实字节：先算哈希，匹配候选声明，再写对应内容地址；已有同名备份必须逐字相等，不覆盖。映射绑定具体 grant。运行后按 recorder 结果验证无输入变化；改动后的代码不能沿用旧源码备份或旧测试结论。

旧捕获的 inputs.json 只有摘要，没有源码原像。禁止倒写或宣称旧捕获已拥有源码备份。此次误删的四个用例仍须从真实旧备份/可信原始会话记录恢复，恢复来源和原断言比对另行记录；数量恢复不能代替语义恢复。无法逐字复原时如实标注差异并逐项核对原规格/已知断言，不称逐字恢复。

新 429 仍按用户规则立即停止，不因本保全规则自动重试或接替。全部失败捕获继续保留。
