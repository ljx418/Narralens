# MAIN：R02旧证明与新稳定读取轮次的边界澄清

本说明依据既有 DESIGN 的一次 readSource C、CONTRACTS 的 retained 闭包，以及 DEVELOPMENT 的 R02/负向验证后新合法 proof 恢复条款。它不增加源码授权，不改变原生写入治理或公共合同。

相同字节被新 inode 替换，必须使已持有的旧闭包、旧 Expected proof，以及替换期间正在形成的读取轮次失效。不能以字节摘要相同忽略该变化；原 FD、目录与身份校验必须保留。

原合同没有要求项目永久拒绝以后所有独立新轮次。替换已经结束且全部权威内容仍与 committed source 一致时，新轮次可以重新取得真实身份并独立核对原 DB、owner、commit/control、rights、producer、全部字节、正负项与目录集合，最后重新验证闭包。这个新证明不复活旧证明，也不授权内容修改。不得调用 prepare 自动清洗副本或删除污染来制造通过。

当前测试在旧 verifyClosure=false 后，要求一次完全新的读取必然抛 COPY_DRIFTED，即把“旧轮次漂移”误写成“新轮次永久不可证明”。应保留旧证明拒绝的严格断言，补充替换发生在异步读取/probe等待期间的拒绝、真实 Expected 对旧 proof 的拒绝，以及明确的新稳定轮次条件。字节改变、未知文件、伪权限、过期 generation 等原拒绝不变。

本批018结果仍是失败记录，不能因静态解释就改为通过。修改测试后须绑定新的冻结输入真实执行；R01–R07其它缺口、回归与独立审查继续必需。整批命令真正结束前不得修改输入。
