### BLOCKER F01 — Verification and negative-walk close failures can remain authoritative

Requirements: R07, R02. With valid membership and a failed temporary close, walk can return true and verify can remain true, losing cleanup evidence and leaking an uncertain allocation. retainAbsent likewise suppresses intermediate-parent close failures; those temporary descriptors are not registered for later closeAll, contrary to its comment. Existing injected-close cases arm at final release or open enumeration, not verification or the intermediate negative walk. This is a static control-flow finding; no fault injection was executed by reviewer.

Proposed, not run: Within existing private resources, preserve every close failure, latch uncertainty before a later proof can verify, and cover verify/negative temporary allocations without retrying numeric FDs.
