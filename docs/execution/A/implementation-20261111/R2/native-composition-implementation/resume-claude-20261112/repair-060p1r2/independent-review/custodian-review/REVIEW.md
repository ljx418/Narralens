## Actual kernel branch and the 28 Python tests

`Custodian._settle_domain:1463` really constructs `TargetSettlement(KernelSettlementOperations(self),...)`. This is not a dead extracted oracle. Its normal loop now checks all live targets rather than only N, and _reap_adopted calls waitpid on each direct non-N child. N is observed with WNOWAIT. However, the mocked `FakeSettlementOperations` in the new unit file supplies its own live list, clock, reap results and ECHILD; those tests do not exercise _collect_targets/_live_targets/_reap_adopted/_reap_worker/_echild as a combined actual branch. No unit proves adopted targets waited before last-N wait under real collection/adoption error. The adapter is wired, but the relevant OS-boundary counterfactual is missing.

The short-write test genuinely calls ControlWriter, and the nonblocking exec test genuinely calls _read_exec_status with local pipes. The GET test calls prctl_get_child_subreaper with an ordinary Python fake and checks pointer shape; it does not call prctl_bind on the actual ctypes function or execute SET/GET. Thus its result is not evidence of real ctypes call conversion/kernel support. The identity tests now locally mock node:child_process before use; IR-10's old real failed interpreter spawn is not repeated by that pure entry.

Collection still loses error detail: group_members skips unknown /proc entries; direct_children unknown becomes an empty reap result; _observe_worker_anchor collapses OSError to false; _echild can call waitpid(-1) after a failed/unfinished N reap. No false full-domain proof follows solely from one missing /proc entry because final group ESRCH and ECHILD are also required, but these branches do not satisfy the claimed retained-owner/complete-transcript behavior. They must not be presented as all repaired by the pure tests.

During TargetSettlement.run, sleep/reap polling does not service the selector or drain N stdout/stderr. Output produced during finalization therefore has neither reliable final byte accounting nor the promised every-phase budget check. This compounds R2-C06; it is not evidence of an observed runtime hang.
