## M级意见

| ID | 位置/问题 | 建议与验收 |
|---|---|---|
| M-01 | 07阶段表同时出现样片接受、首章接受、章节接受、QC人工决定；08又保留采用批准。若每个术语都实现成按钮，会违反“不密集询问” | MAIN拟增加的一次review+adopt映射应覆盖：用户在同一已展示版本/影响范围的一次“接受并应用”同时形成内容决定与精确采用批准，服务端仍分别记录并原子消费；普通内容接受不能自动授权未展示未来变更。首章检查与常规首章审阅同包同决定；同摘要整章小样复用。验收记录实际人类点击次数与每个决定用途，不出现“已接受→再确认同样内容” |
| M-02 | 08 §4影响审阅期间旧计划继续运行，步骤4已正确防止热换，但没有写清准备patch是否暂停相关dispatch/预留资源，以及何时释放 | CP固定一种策略并展示：默认旧计划继续，patch只是候选，用户知道期间可能stale；或显式暂停相关尚未dispatch子图并持久记原因/恢复。不得隐式全局暂停、无限持有GPU资源，或在用户拒绝后留下僵尸等待。验收：审阅期间节点开始→旧patch stale，拒绝/失联/超时后原计划与资源状态均可解释且无重复dispatch |
| M-03 | 07 §3允许不兼容变化使稳定授权失效，08清单简写“版本/风格变化使旧授权失效”。稳定scope还需明确运行内何时检查与对已越门部分的影响 | CP给出兼容性与scope精确规则：固定模板execution_digest、风格、内容类型与相关能力/模型指纹；兼容补丁是否沿用不得由Agent自报。每次跨首章门前重新核验；撤销/不兼容改变只阻止尚未越过的依赖，已授权在途任务不自动kill，取消另走受控流程。验收：相关模型替换/风格改版/跨内容类型/撤销均阻止未越门制作；不相关已完成分支保留；单纯重连不要求用户重新签稳定 |
