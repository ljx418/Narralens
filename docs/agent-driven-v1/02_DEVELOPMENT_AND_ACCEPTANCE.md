## 2. AD-S1：服务入口、Skill 与客户端接入

用户可见结果：双击图标打开服务状态和工作台；一个驱动 Agent 加载入口 Skill 后可发现本机能力，读取持久项目与当前选区。

模块与顺序：
1. 生产 ServiceSupervisor / instance discovery / stop/recover；旧 M5 临时入口保留独立标签。
2. Host 应用服务边界与版本化 capability registry；只把真实通过能力标 available。
3. MCP façade、tool/resource schema、鉴权/路径/错误映射；stdio 客户端只连常驻 Host。
4. 入口 Skill 与 read/context/recovery 子技能；将方法版本和工具协议版本分开。
5. Codex 首端真实接入；Claude Code/DSH 真实探针形成支持矩阵，失败保留原因，不承诺一致。

R2补充：只读扫描/登记Comfy模板、区分canvas/api/envelope、依赖与输出节点预检，建立blocked/候选能力；不加载全部模型预热，不提交prompt。结构化提问/回答与工作流read model的schema同批冻结。

验收：`AD-T01` 双击冷/热启动与停止重开；`AD-T02` tools/resources discovery、schema 拒绝、无权限/错误版本拒绝；`AD-T03` 两客户端查询同一 project/job/snapshot；`AD-T04` 服务不可用时 Skill 给出明确下一步且不另建库。原 Host/auth/路由负向回归必须保留。人工只核对启动与能力呈现，业务测试 Headless。

轮内退出：首端真实接入、基础门绿、内部增量检查；三个客户端的实际可用/blocked 均有明确矩阵后连续进入S2。独立组合外审在迭代A末统一执行，不在S1单独增设外审停点。没有DSH实测不能宣称DSH兼容。回退：关闭新MCP/生产入口，旧入口与工程文件保留；schema迁移需备份/重开证明，不删除新数据。

## 3. AD-S2：第一个真实短片闭环

用户可见结果：向 Agent 给想法和本地授权素材，创建持久工程，得到 60–180 秒真实可编辑初稿和可带走的 MP4，关闭后能继续。

模块与顺序：ProjectCreationService → general ProjectResolver/WorkbenchProjection → CreativeTask/Artifact/Checkpoint → 结构化脚本/分镜提交 → 本地资产绑定 → 原生工程初始化/采用 → committed snapshot render → 最小 QC 与交付。外部 Agent 负责创作推理；内部 Runner 不强制再次生成。

必须实现：不复制固定三镜 fixture；创建输入与初始快照受服务端验证；每镜可编辑；未确认的结构化草稿与已提交工程分离；外部 Agent 退出不删除 Host 任务；本地 export 不依赖新付费服务。

R2补充：初版即显示可读业务图与节点输入输出，启发问题在界面可回答；用确定性文字/SVG/原生图形制作一段概念说明，避免“漂亮但无内容”的短片。选定一条本地生图与一条短视频模板安排隔离真实探针，未验证仍blocked；Comfy生产采用闭环留在S4。R3明确A轮采用本地授权素材即可完成，不因可选Comfy探针阻塞首链，也不声称A轮已经通过Comfy验收。

验收：`AD-T05` 两个不同选题建不同真实工程、幂等/失败清理；`AD-T06` Agent 通过 MCP 从任务到可编辑影片、真实渲染并完整 decode；`AD-T07` 关闭服务/重启，project/history/snapshot 对齐；`AD-T08` 改一镜再导出，比较不变区与两份产物；`AD-T09` Agent 在准备/执行/结果返回边界中断、重连读取 checkpoint，不重复提交。使用实际录音/授权本地媒体，不用空音轨假装配音完成。

人工门：用户只提供内容与素材、确认摘要和一次修改，实际带走短片；记录人工步骤、耗时和失败。通过只可声明 `AD_SHORT_FILM_READY`，不是 V1-P0 或 V1-Full。

回退：停用新建入口；已经创建的项目仍可读/导出，不能删除或伪造成迁移工程；失败事务按原 journal 恢复。

## 4. AD-S3：工作台与 Agent 协作、精修与接管

用户可见结果：真实选择方案 B、观看前后差异、提出局部修改、确认/拒绝、撤回；Agent 自动读懂人工决定。更换驱动能继续，不覆盖手工修改。

模块：CandidateReview（proposal/proxy 明确绑定）→ DecisionService/ApprovalInbox → ChangeReview（前后范围/内容/保留项/许可/费用）→ Selection read model/version → DriverSession/fencing → 持久 workflow 检查点与所有现有 history/锁接线。

R2补充：NodeInspector/ArtifactRevision/DependencyImpact→工作流节点单独编辑与局部重算；AssetPlan按主题/章节/镜头台词分阶段；ResourceScheduler先落地IO下载和CPU章节/音频child jobs并行，DriverSession只限制编排者。已提交影片不因编辑草稿而改变。

普通准备和低风险执行在既定授权内连续推进；工作台把 prepare/poll/impact 映射为可理解的“准备预览/查看修改/确认应用”，不能只是把内部步骤藏起来却绕过验证。3–6 方案必须每个可选；选择不立即改工程。

原 PRD §5.4 的入出点、缩放、裁切、字幕、速度、关键帧，以及音轨/过场等承诺，必须逐项形成 `PostEditCapability` 实现与真实渲染矩阵：可支持者经 typed intent 接 Coordinator；未支持者阶段内可明确禁用，但仍是未完成规格，不能因显示 disabled 就算 V1 达成。跨镜自由变形等原明确排除项不扩张。无法支持的承诺只能走显式 PRD 变更由用户裁决。

验收：`AD-T10` 任意选案往返、修改选择使旧候选 stale；`AD-T11` 人类 UI 选区→Agent 局部处理→前后对比→一次提交；`AD-T12` 许可/锁/base/impact/approval 负向、成功+1失败+0、禁止跨项目复用批准；`AD-T13` 两 Agent 争抢/租约失效/迟到结果/显式接管；`AD-T14` 人工编辑后旧 Agent 409、不覆盖，恢复新 revision；`AD-T15` 核心路径键盘、文字状态、主题、真实预览稳定与 Headless 截图。

体验门限：不读教程即可知道当前状态和下一步；首次定位/比较≤60秒、找到恢复≤10秒，学习后计时单列；能解释前后差异、保留对象和提交结果。发现信息不足判未通过。S3在B轮内通过增量门后连续进入S4，正式独立外审与人工体验在B轮末集中完成；不得单凭组件测试签 `AD_COLLABORATIVE_EDITING_READY`。

回退：关闭新协作入口并释放/撤销驱动 session，保留 decision/approval 审计；内容回退通过原受控 restore，不手改 pointer。

## 5. AD-S4：检索下载、声音字幕与完整交付能力

用户可见结果：Agent 在授权范围内准备在线素材、配音和字幕，展示来源/许可/费用；工作台审阅标题封面与 QC，生成完整交付包。

模块：ProviderGateway 与最少一个许可检索/下载能力 → ASR/TTS/Alignment → 来源/rights/receipt ledger → 标题8/封面4实际候选 → Preflight/Delivery。所有能力先探针固定版本/许可/可用性，再接生产；不建设插件市场。若 provider 不可用，接口 blocked，不能用 fixture 算真实服务通过。

R2补充：优先复用本机ComfyUI，固定至少一个图像模板与一个短视频模板；实现ComfyAdapter与GPU槽、prompt/外部子job关联、验证与AssetRegistry接线。支持概念背景+可编辑图形层、首尾帧转场候选；后期复用已有分批执行器而非重复造RIFE/SeedVR2服务。不把依赖缺失的全库作为首期目标。

验收：`AD-T16` 查询/许可/下载分离，大小/流式/取消/重定向/SSRF/缺盘/路径负向；`AD-T17` 本人录音和授权 TTS/ASR/字幕版本对齐，实际中文音画，画面改动不重算锁定音频；`AD-T18` 费用 reservation/receipt/unknown 对账、429/422/529、取消后晚到、重连不重复扣费；`AD-T19` 标题8/封面4与正文事实风险、source/synthetic/rights 完整；`AD-T20` 真实 QC 阻断、snapshot-bound 导出与附属文件哈希。

授权：不推断本轮允许真实付费/外传；没有授权先完成本地与非外传部分，列具体调用范围再等待。预算按用户批准范围配置，不能偷设硬性次数/额度上限，也不能无界重试或把未知费用记0。

人工门：选择一份真实配音与封面，核查字幕/声音/标题正文；完成一条真实目标短片。只有所有 P0/NFR 和对应长片章节条件也通过，才可按原口径签 `Gate V1-P0`，不能仅凭 S4 任务表完成宣称通过。

回退：禁用失败 provider 能力，保留已登记资产/receipt/unknown；不得因服务更换覆盖原资产引用。

## 6. AD-S5：全 V1 验收与多驱动接力

用户可见结果：同一 10–15 分钟项目完成研究→脚本→素材→初稿→局部精修→声音字幕→风格→标题封面→QC→交付→反馈，并可跨窗口恢复。

模块：StyleProfile 版本与影响/回退、评论锚点与 orphan、剩余 P0/P1 缺口；Codex/Claude Code/DSH 全适配和真实接力。首端通过不等于全兼容，DSH 若实际不支持，保留 blocker 并由用户决定兼容路线/明确缩范围，不能自行豁免。

验收：`AD-T21` 完整真实10–15分钟母项目、3–5分钟20+镜章节、3处修改、关闭服务重开/恢复/双导出；`AD-T22` 三驱动分别执行发现→准备→查询→审批→应用→恢复→交付，再做接力，选区和版本一致；`AD-T23` 风格应用/局部override/锁/回滚和反馈锚点；`AD-T24` 100+镜性能、四类操作各100样本p95≤100ms（既有指标），首帧/掉帧/渲染时长与峰值资源预算在跑前按参考机冻结；`AD-T25` P0/P1/NFR/AD-E逐行证据、独立审查、中文可视化报告与人工签署。

退出：P0/P1/NFR 与 AD-E01..21 无 partial/blocked/NOT_RUN，无未关闭重大问题；外审绑定冻结 commit；真实长片产物、全部测试/安全/媒体/性能/恢复与用户签署齐备。只此时允许 `V1-Full`。人工内容事实/审美不由 Agent 自签。

回退：按阶段能力开关禁用；保留工程/资产/版本与证据，受控恢复内容；不 force push、不 reset 用户项目。

## 9. 团队流程与每阶段 DoD

1. 先冻结该阶段完整垂直链的合同、原型状态、DDL/兼容、case、回退与声明上限；代码前审查闭环。
2. 责任分开：实现者做实现与自审；独立审查者审冻结 commit；用户负责内容/审美/高风险授权。外部驱动生产视频的身份不能拿开发权限绕过 MCP。
3. 按可观察能力提交；模块之间运行受影响回归，不逐模块做完整外审；阶段末统一全量与独立审查。
4. 每 ticket 交付代码/合同/测试/复现命令/exit/日志/逐case与 SHA256 产物；证据绑定干净 capture commit，失败捕获不覆盖。
5. 真正的进程退出、客户端掉线、取消、资源失败、并发必须有直接门；只做函数桩不能宣称生产接线。
6. 自动化一律 Headless、静音、无抢焦点；服务和浏览器按实例清理；人工启动提前通知。UI关窗不删生产工程。
7. 规格检视与内部四视角：产品、架构/安全、实现/恢复、测试/证据；独立外审绑定冻结代码，修复后跑受影响回归与新冻结。
8. 同阶段第3次返工由当前负责 Agent 聚类根因并接管闭环，只有产品/契约/授权/人工事实缺失才升级，不机械退回。
9. 禁止全目录 git add；保留用户修改，显式路径提交；不自动合 main 或外传素材。阶段报告包含未执行、限制、外审与人验状态。
