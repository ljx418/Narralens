1. MAIN发布大阶段任务书，明确目标体验、范围、公共合同、任务DAG、所有权、资源与人验门槛，并向用户汇报实际分工。
2. 领域Codex先核对代码事实，提交详细架构、具体实体/调用与状态关系、接口消费、异常恢复、测试矩阵和证据方案。
3. MAIN审核跨领域一致性，关闭重大歧义，发布绑定完整base/contract SHA的任务释放记录；未释放范围不得实现。
4. 领域Codex给所属ClaudeCode完整任务包；Claude连续实现、局部自测及修复，领域Codex分时只读检查，必要时安排设计修订。
5. 领域Codex复核生产接线、正负向场景和证据，冻结领域候选，向MAIN汇总；组件通过不能代表真实集成。
6. MAIN按依赖集成，真实producer/consumer联调；大阶段统一冻结、适用全量回归、四视角审查与独立复核，出具中文HTML真实证据报告。
7. 服务与报告就绪后停在人验入口，用户签署；不把每个模块变成人工审批点，不在上一阶段门未满足时跨入依赖阶段。
