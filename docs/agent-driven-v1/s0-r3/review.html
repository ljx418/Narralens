完整页面划分、操作边界与分工

S0 R3：顶部工作流Bar与独立系统控制

用户最新要求：工作流是顶部可折叠、横向布局面板；第二块是系统控制，展示并控制本项目服务加载、模型装载、预热、卸载与重试，不是Agent控制台。R2前端方案由本版替代，历史冻结保留。当前只做设计与宿主生图，不进入生产实现，不实际装载模型/启动停止服务。

页面划分

1. 全局顶部：约44px的工作流摘要Bar，显示项目、当前步骤、目标范围、等待原因、Host commit与编辑区已加载状态；展开后为约120–180px横向步骤图。展开占布局空间，不盖时间轴；收起保留最新摘要和错误提示。小屏允许流程区横向滚动，原生精剪沿用既有桌面尺寸条件。

2. 原工作区：OpenFilm素材、播放器、检查器、时间轴，以及右侧M5导演面板保留。原有选案/批准/编辑/历史继续走既有入口。工作流节点只复查与定位，不新增第二时间轴、播放时钟或聊天工作台。

3. 顶部“系统控制”入口：用户显式打开独立面板/抽屉，默认关闭；含服务、模型、重试与诊断。它不占用导演面板栏目，不是Agent终端镜像。关闭仅收起管理视图，不关服务或卸载模型。

系统控制的内容与行为

- 服务：实例归属、进程存活与API就绪分开、依赖检查、观察时间；自有实例可按权限启动/预热/停止/重启。共享服务只提供连接/只读检查，不擅自kill或清队列。

- 模型：只展示已登记配置及依赖/许可，标识未加载/装载中/就绪/执行中/卸载中/失败/未知；模型在磁盘上不等于已驻留，更不等于生成能力就绪。按需加载、预热、卸载分别是受控任务，需runtime可验证的资源/状态回报。

- 活动任务：显示资源占用来源与受影响任务；执行中禁止直接卸载或重启破坏任务，提供等待安全点/明确取消自有任务的可选路径。无采样显示未知，不填0。

- 重试：重试健康/依赖检查与重新执行媒体任务分开。后者需重核输入版本/许可/授权/幂等键；外部结果未知先查证与对账，不能盲重提或重复扣费。

- 安全范围：受信UI会话触发、按实例与runtime归属控制；不把控制权给任意Agent参数，不读凭据、不执行任意Shell，不自动下载模型或安装节点。

架构与分工修订

PRODUCT负责WorkflowTopBar、SystemControlPanel及typed UI适配；MAIN从现有M5 React根通过布局插槽/portal做最小接线，保持单root/selection/clock，管理命令由MAIN应用端口授权。BRIDGE负责服务发现/就绪/健康和监控投影；MEDIA提供受控ModelRuntimePort与worker能力/模型状态。模型控制不直接写工程revision；视频编辑仍经原Coordinator。

A轮优先实现真实顶部工作流可见性、项目自有服务控制与模型登记/不可用原因；未接管或未验证runtime不开放加载按钮。B轮在受控本地生成runtime与GPU调度接通后验证真正模型加载/预热/卸载、取消与恢复。不把Comfy全库或所有模型一次加载作为启动前提。S0/A/B/C与17包不增加；实际开工前另报详细任务分配，阶段末统一验收。

设计验收重点

- Bar横跨顶部，折叠/展开后仍是原工作台，当前步骤和错误不会在折叠时消失。

- Job完成、Host提交、编辑区已加载三者分开；人类选区/草稿不被新事件覆盖。

- 系统控制是模型和服务管理，不是Agent聊天/日志控制台。

- 共享实例只读、执行中卸载受阻；未知状态清楚、失败有可解释的重试路径。

- AI效果图只说明布局和视觉，不作API/资源/实际功能证据；精确交互以HTML与本文为准。
