# 创作者交互优化建议（待核对，不是实现合同）

本文件是本轮UX检视的建议，不替代S0 R3候选或PRD，不释放生产开发。保留现有OpenFilm编辑器、单一选区/时间轴/播放时钟与M5导演面板；新增顶部可折叠横向工作流与独立系统控制的方向保持。

## 创作者主线

已有工程：选择镜头 → 说明希望改变的内容 → 等待候选 → 看差异与预览 → 确认采用 → 确认编辑区已更新 → 继续精修或进入交付。

从想法开始：确认简报 → 审脚本与分镜 → 审初稿 → 按同一改单镜路径精修 → QC与交付。此路线属于PRD目标，不代表当前界面已具备完整端到端能力。

线性的是人类的决策顺序；素材、声音和其他后台任务仍可并行。不能为了做向导阻断原生剪辑、强制逐节点点击或新增一套工作流权威状态。

## 组件责任与信息层级

| 区域 | 默认可见 | 按需展开 | 不应承担 |
|---|---|---|---|
| 顶部工作流Bar | 当前目标、范围、正在进行/等待我的事项、更新时间/失联提示、定位当前事项 | 创作者阶段与分支；节点输入输出；提交和编辑区版本 | 第二份审批表单、聊天、第二时间轴 |
| 现有导演面板 | 当前任务、当前候选、变化摘要、当前主动作 | 其他候选、保留项、影响明细、锁、历史、来源 | 手填comparison ID等日常技术操作 |
| 原生播放器/时间轴 | 当前画面与真实选择、播放和原生精剪 | 同一播放区切换当前/候选；可选比较视图 | 新建一套独立播放时钟或选区 |
| 独立系统控制 | 显式打开后显示项目所需服务/模型、阻塞与恢复 | 实例归属、探测、资源、脱敏诊断、受控管理 | 抢占日常创作主按钮或成为Agent终端 |

创作决策区每个状态只有一个主要动作；取消、返回和更多操作可作为次要动作。系统控制在正常创作时使用弱入口，有实际阻塞时展示影响并提供定位，而非常驻高亮。不强制把所有面板的信息数量都限制为相同值，素材库可保持专业密度，决策区需要收敛。

## 状态与动作建议

| 真实状态 | 创作者可见说明 | 主要动作/反馈 | 技术约束 |
|---|---|---|---|
| 尚未明确目标 | 选中的镜头与希望改变的内容 | 提交创作目标或查看Agent提案 | 不新增未实现的生成入口假功能 |
| 准备候选 | 正在准备什么、是否等待资源、最近回报 | 查看进展；取消为次要操作 | 无真实百分比不造进度 |
| 候选可审阅 | 当前/候选、变更范围、保留项、来源 | 查看/比较候选 | 先预览，不自动采用 |
| 需要确认 | 明确本次会改变什么、保留什么及影响 | 确认采用 | impact/base/锁/许可检查继续保留，失效须重核 |
| 正在提交 | 正在写入工程 | 等待明确结果 | 受理、Job完成、提交成功分开 |
| 已提交但编辑区未确认 | 工程已提交，画面同步待确认 | 查看同步状态 | 不把commit当原生界面已加载 |
| 编辑区已确认 | 当前镜头已更新，可继续检查 | 继续精修或进入交付检查 | 以原生版本回报为证 |
| 阻塞/失联/失败 | 影响哪个目标、保留了什么、下一步可做什么 | 定位阻塞或安全重试 | 外部结果未知先查证，避免重复执行 |

主动作复用原导演入口。顶部“定位当前事项”只移动焦点/滚动到同一入口，不新建另一套批准能力。前置准备可自动串联，必要审批不被合并跳过。只有实际支持的取消与恢复才开放操作。

## 视觉与布局建议

- 当前目标与待决定事项优先，版本/ID/帧号降为明细；用户名称与秒数优先，精剪时仍可查看帧与技术标识。
- 折叠Bar建议约48–56px；展开阶段条建议约96–120px。数值为下一轮可验证假设，未经批准不写成冻结合同。
- 展开后仍须在常用1366×768与1440×900下保留可操作的播放器、原生时间轴和当前决策入口；如空间不足，应收敛工作流明细而非遮挡编辑器。
- 完成阶段降低视觉权重，当前阶段突出，未来阶段简写；避免六张同样大小的卡片长驻。
- 三路比较能力保留，但优先当前选中的候选；另两路按需展开/切换，不默认挤满导演栏。音频焦点和播放同步沿用现有机制。
- 系统控制仍独立；日常查看优先非模态管理面板/独立视图，危险确认才短时模态。关闭后返回原选区、草稿和焦点。

## 下一轮原型的验收任务（尚未执行）

1. 首次查看后，用户能指出当前目标、Agent正在做什么、是否需要自己行动；记录实际观察，不以Agent猜测代签。
2. 完整演示“候选准备→查看差异→确认采用→已提交→编辑区确认→继续精修”，步骤与数据均标明模拟；不能只测按钮能点。
3. 同一流程演示资源阻塞、影响过期、断线重连和结果未知；不丢选区/草稿，不盲重提，不假报成功。
4. 在1366×768、1440×900和窄屏审阅模式核查密度与可达性；窄屏不宣称完整原生精剪支持。
5. 键盘验证工作流当前步骤语义、系统Tab切换、Escape退出与焦点返回；动态状态可被辅助技术感知。
6. 抽屉打开/关闭及工作流展开/折叠均不改变工程、选区、播放时钟或待批内容；生产接线时用真实事件另验。

以上先由交互原型验证，用户核对后再同步PRD、组件规格、合同与任务分工，避免把未认可建议直接交给实现Agent。
