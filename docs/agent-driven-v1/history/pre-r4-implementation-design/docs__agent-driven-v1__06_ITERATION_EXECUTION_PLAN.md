## 1. 目标与推进顺序

整体目标：外部Agent经Skill/MCP驱动持久项目，工作台能启发式补全需求、实时呈现业务工作流、查看/单独修改产物、监控服务和资源；通过真实素材和本地Comfy生产视频，完成精修、质量检查和成套交付。

开发按三轮垂直交付组织，轮内以任务包提交，模块检查不中断到人类逐个审批。每轮正式冻结一次候选，集中组合全量回归、内部四视角审查、独立外审和人工目标体验。审查发现问题在该轮闭环，不把失败重命名为下一轮。

| 轮次 | 阶段 | 用户最终拿到什么 | 正式组合出门 |
|---|---|---|---|
| 准备轮 | AD-S0 | 可操作目标原型、冻结的首轮合同/测试/迁移/回退与授权范围 | DOC_READY：原型与实现准入另行明确；当前尚未达成 |
| 迭代A：真实短片 | AD-S1 + AD-S2 | 双击启动，Agent问需求建项目，工作台实时显示流程，完成60–180秒影片；改一镜、关服务重开后再导出 | AD_SHORT_FILM_READY，仅短片/首端范围，不是V1 |
| 迭代B：协作与完整制作 | AD-S3 + AD-S4 | 任意选案/节点产物编辑/局部重算，镜头和章节并行，监控/接管，分阶段下载，Comfy/配音字幕/标题封面/QC | AD_CREATION_BETA_READY；V1-P0必须另外证明原全部P0及章节门 |
| 迭代C：完整V1 | AD-S5 | 真实10–15分钟项目、多驱动接力、风格/反馈/全量后期、完整交付与恢复 | P0/P1/NFR/AD-E全绿并人验后V1-Full |

迭代A使用本地授权素材与实际录音，可先用确定性概念图形；Comfy隔离探针不冒充生产接入。迭代B将本地生成真正接入资产/剪辑/渲染。不能因Comfy依赖未就绪而把持久短片无限延后，也不能在Beta报告中略过未通过AI能力。

## 2. 实施前置与合同包

AD-S0完成以下可审核交付，不能把当前文档示意直接当产品原型通过：

1. 依现有工作台逐阶段制作增量原型：两块观测面板、定位原选案/差异/批准/历史入口、监控、断线/错误与原生同步；其余业务继续复用原控件；模拟部分明确标识。
2. 首轮合同：production instance与auth、MCP tool/resource注册、创建项目与origin、artifact版本/工作流/Decision、审批、job/事件/cursor、导出snapshot、错误与兼容矩阵。
3. 同步runtime schema/TS/validator的预期定义与黄金向量；DB表/索引/CHECK/迁移/旧库重开方案；不新建第二事实库。
4. 首轮实际case步骤/fixtures/输出断言、负向矩阵、真实CLI调用与无窗口证据方案；任何需外传/费用单列授权。
5. 确认服务归属、生产项目目录、实例凭据保护/恢复、owned/shared Comfy边界；具体路径不能由Agent任意传入。
6. 固定客户端/协议包/依赖与许可证；Codex作为推荐首端，Claude Code/DSH先做只读能力探针。DSH不支持时记录阻塞并比较兼容方案，不隐式删减最终目标。

冻结分层：跨三轮的不可破坏原则现在锁为设计约束；首轮精确接口在开工前冻结；后两轮先冻结稳定消费边界，详细schema在各轮开工前闭环。禁止假称“全部未来合同已精确冻结”，也不为设计未决定的细节提前实现临时API。

## 4. 迭代A：先拿到可带走的短片

### A的实现顺序与最小闭环

生产服务生命周期先成立，再提供MCP和一般项目创建；MCP只映射Host应用服务。创建的项目不得伪造migration record，WorkbenchProjection/资产inventory/引擎绑定/初始snapshot同步支持new与migrated origin。

外部Agent提交结构化问题和脚本，可信用户答复/批准落Decision。首端调用不强制再次启动内部Agent。首轮至少允许选择一个明确的方案并组装真实原生工程；不能继续使用固定第一份录制提案作为唯一入口。完整3–6方案对比在迭代B补齐。

当前selected input→prepare→impact→批准→apply路径必须在A中真实接通；不能先给Agent unrestricted filesystem写入临时绕行。A先满足有界单驱动与可信批准，B再补齐多驱动接管与完整竞争矩阵。

最小render runner在A交付，B扩展输出包/QC，C做长片。三轮共用同一实现实体，不能在A写“临时导出器”到B推倒。A的任务事件、幂等/重开、snapshot-bound输出和错误语义也必须生产接线。

### A的出门证据

- 两个实际不同主题创建不同持久工程；不用三镜fixture复刻任意输入。
- 一名真实外部Agent经MCP在授权输入范围内完成从简报到原生工程；记录工具调用、输入/输出hash和job/transaction lineage。
- 一条60–180秒中文录音/真实授权本地素材影片；真实编码、完整decode、ffprobe、字幕/画面抽查；至少一段可编辑概念说明。
- 修改一个镜头后第二次导出，变化与不变区正确；revision/commit/snapshot一一对应。
- 退出Agent、关闭工作台、停止/重启自有服务后重新打开同一项目；工作流与工程可恢复，旧任务不重复执行。
- 实时业务图不靠手动刷新，服务故障有明确状态；达到A适用的T32/T33/T35，不把完整监控面板提前算通过。
- 用户实际带走视频并确认“能完成一次任务”；通过也只宣称短片首链，不宣称Beta/V1。

### A人工门之前的阻塞处理

DSH兼容、全部Comfy模型、在线下载或TTS未就绪时，A可以按已冻结的本地/首端范围完成；记录受限，不提前声称这些能力。若新建原生工程、正式渲染或MCP真实连接不通，则修本轮，不改成演示片或让人手改JSON。

## 5. 迭代B：协作体验、制作能力与实时监控一次闭环

### B的实现顺序

先建立NodeInspector/ArtifactRevision/DependencyImpact与AssetPlan，再实现任务并行和驱动接管。资源准备仅产出不可变候选；正式工程写入仍经原Coordinator。多个章节的中间视频/音频可并行生成，不能并行直接改同一author source。

依赖细分：IT-B02提供通用有界下载/CPU执行器与资源调度测试接缝，先用受控来源和隔离任务证明并发/取消；IT-B04再接真实检索provider、许可、分阶段AssetPlan与在线下载端到端，补齐T28生产证据。前者通过不提前关闭后者的真实素材下载验收。

监控与事件恢复在接大模型前补齐，避免先接GPU任务却无法解释等待或中断。MCP与UI都读取同一workflow/job/health事实。Host断开仍由独立supervisor提供有限状态，无法确认时unknown，不缓存绿灯。

Comfy按“发现→格式转换/固定模板→依赖探针→一图一视频真实smoke→质量→生产接线”推进。复用本机模型与已有分批执行器；模板封套、自定义外部子job、output/type、资源占用和取消能力逐项记录。不能把Comfy history完成当作所有外部任务完成。

之后把授权下载、声音/字幕、标题封面和完整QC/交付接同一资产/任务体系。新付费/外传保持独立授权，不推断文档批准包含实际消耗。

### B的组合验收

- 工作台选择任意分镜方案；Agent读取同一决定；前后对比能解释改动、保留项、费用和许可。
- 单独修改脚本/素材节点，重算范围只覆盖依赖消费者；旧产物与已提交工程保留，锁定旁白/独立章节不重算。
- 并行镜头下载、章节拼接与音频合成有真实运行证据；资源不够时waiting_resource；GPU并发按实测容量，不复制大模型堆满内存。
- Comfy一图一视频实际产物进入AssetRegistry→原生clip/图形层→预览→受控采用→真实渲染；术语/数字/关系可编辑并人工核查。
- AI转场首尾/handles/总帧/音轨正确；主动选择普通转场的记录与AI能力通过分列。
- 监控实测服务ready/degraded/offline/unknown、队列/资源、Last observed/TTL、故障定位、断线恢复和共享服务控制边界。
- 授权TTS/ASR/字幕、8标题/4封面与QC/来源许可齐全，错误/未知扣费/晚到结果不重复调用或采用。

Beta通过不等于V1-P0。若该轮实际完成原13P0、6NFR与3–5分钟20+镜章节全部证据，可单列V1-P0审查；缺项保持未关闭，不为一次过审而缩减要求。

## 6. 迭代C：完整长片与V1终审

保持B稳定契约，补齐StyleProfile、反馈锚点和未完成的原PRD精修操作。裁切/缩放/入出点/字幕/速度/关键帧及声音操作逐项验证；不支持的承诺必须实现或由用户明确批准规格变更，不能仅显示disabled算完成。

在真实10–15分钟母项目内完成3–5分钟20+镜章节、至少3处局部修改、恢复、重开和双导出。全片保留所有原生可编辑clips和资产关系，不用整片扁平MP4代替可编辑母工程。

三驱动分别跑标准调用链后再做接力；不能只安装配置就声称兼容。DSH若缺MCP能力，提出适配/替代/范围选择，未经裁决保持对应项blocked。

正式冻结绑定代码/合同/配置/固定上游与模型/素材/机器信息，旧Gate历史只做适用回归，不改其冻结后无变化门；使用已有historical验证方式与本轮current-tip门分开。最终只有全部P0/P1/NFR/AD-E真实证据、独立外审与人工签署齐备，才声明V1-Full。

## 7. 每包与每轮的工程流程

每包：读本轮合同→列责任实体与case→实现→类型/契约/架构fitness与受影响回归→真实接缝验证→显式路径提交与追加证据→自动进入同轮下一包。

每轮：组合冻结→真实数据端到端→PRD规格检查→内部产品/架构安全/实现恢复/测试证据四视角→独立外审→修复并新冻结/受影响复验→中文HTML报告→用户体验/签署→按已授权范围提交同步。

默认不在包完成后要求人工确认。仅在需要真实人工验收、改变产品/架构契约/高风险授权、外部不可绕阻塞或用户明确要求交给Claude Code实施时停止。第3次返工由当前负责Agent接管共同根因，不机械移交原问题。

不可通过放宽超时、删负向断言、挑选通过捕获或把未知原因归类为环境噪声来闭环。Headless/静音/无抢焦点；测试实例与浏览器在finally清理；生产项目不得被测试清理脚本删除。
